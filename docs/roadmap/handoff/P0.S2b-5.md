## Deviations (dated 2026-11-08, CLAUDE.md §3a.12)
- **Plan deviation 1:** the storefront runs on **3001**, not 3000 (`http://demo.localhost:3001`). Follow-up: the brief line saying `:3000` should be corrected to `:3001`.
- **Plan deviation 3:** the rewrite target carries the locale (`/_t/{storeId}/{locale}/…`, the store's default locale). Prefix negotiation stays in P3.S2.
- **Plan deviation 9:** of the ADR 0006 D4 cache rules only the ≤ 6 h TTL cap is implemented. Deferred to P3.S5: the TTL policy, the 512 KB entry limit, the writes-off switch, gzip, the in-process LRU, and a node-local api check in `/readyz`.
- **Plan deviation 15:** the storefront `/readyz` returns 200 with Redis down and reports `checks.redis.ok: false` (the cache degrades to a miss).
- **No `app/%5F404/page.tsx`.** Under `cacheComponents`, a page that calls `notFound()` is prerendered as an error shell whose markup renders only in the browser. Making it dynamic is refused by the build. With no `/_404` route, Next's own not-found route serves `app/not-found.tsx` server-side with status 404. A later `/_404` route must keep server-rendered markup.
- **`partialPrefetching: true`** in `next.config.ts`: Next 16.4.5 warns when `cacheComponents` is on without it.
- **`next start` with `output: 'standalone'`** only warns, so the host `start` script keeps `next start` and the image runs the standalone server.
- **`REDIS_URL` and `NEXT_DEPLOYMENT_ID` default only in development and during `next build`**; anywhere else the server exits at boot.
- **Storefront logging is `console.warn(JSON.stringify(…))`**, not the structured logger of §3a.8: the storefront has no logger yet (observability session). Errors are never silent, and repeated ones are de-duplicated.
- **`readCacheConfig` takes `NodeJS.Dict<string>`** because Next's types make `NODE_ENV` required on `ProcessEnv`.
- **`eslint-rules.test.ts` warms the ESLint config in a 30 s `beforeAll`**: loading `eslint-config-next` made the first lint exceed 5 s.
- **The architecture scan excludes `apps/**/.next/`** (generated output; sources are still scanned).
- `useCacheEntryKey` / `useCacheTagKey` are imported under aliases: the React hooks rule treats any `use…()` call as a hook.
- **The Dockerfile tests moved to `dockerfile.test.ts`** (the 300-line limit). More extra tests are listed above.
- **The evidence deployment id is the last image-relevant commit**, not HEAD. Committing the evidence must not change the id it records.
- **Screenshots are committed evidence** (ruling P5-3) in `docs/evidence/P0.S2b-5/`, not `docs/roadmap/assets/p0-s2b`. There are 6 shots instead of the plan's 2, plus API transcripts.
- The pages are bare unstyled text with `lang="en"`. The store locales (ar, fr) have no visible effect until P3.S2 (per-locale layouts) and P3.S3.

## Gotchas
- **Turbopack ignores the `@cod/source` condition:** the storefront bundles `packages/shared/dist`, so `@cod/shared` must be built first (`dev` depends on `^build`, and so does `pnpm build`).
- **A host-run standalone server needs `HOSTNAME=0.0.0.0`.** With `127.0.0.1` it treats its own proxy rewrites as external and fails.
- **Next copies `apps/storefront/.env` into a host standalone build.** The Docker image has none (`.dockerignore`). On a host only an empty `REDIS_URL` counts as missing.
- **`next-env.d.ts` is generated** (git-ignored); `typecheck` runs `next typegen` first.
- **The storefront and a containerised storefront both use port 3001** (like the api on 3100): run one at a time.
- **After a bare local image rebuild** (no exported id), flush the old cache:
  ```bash
  docker compose exec -T valkey valkey-cli --scan --pattern 'next:*' | xargs -r docker compose exec -T valkey valkey-cli del
  ```
