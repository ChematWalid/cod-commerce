# Handoff — P1.S3 (Permissions catalog & roles)

## Done
1. **Catalog.** 93 permissions in 12 areas with sensitive flags and AR/EN labels, in `packages/shared/src/permissions/`, plus the area expansion rules.
2. **`plugins/rbac`.** Vendure permission definitions, `requirePermission(key)`, seven built-in roles per business, custom roles (create, update, delete, duplicate, start-from, area levels, per-permission toggles), store-scoped member access and an activity log. GraphQL and REST.
3. **Provisioning.** Built-ins are seeded inside the provisioning transaction through tenancy lifecycle hooks. Existing businesses converge on every migrate, keeping the owner's Vendure Role id.
4. **Dashboard.** Roles table, New role dialog, Activity log page.
5. **Gates.** `handler-permissions` in `test:arch` fails any `@Query`, `@Mutation` or REST route without `@Allow` or `requirePermission`. Stock Vendure permissions in `ENGINE_GRANTS` need the reviewed allowlist, empty today.
6. **Evidence.** `docs/evidence/P1.S3/` from `scripts/evidence/P1.S3.sh`, including a role change taking effect on the member's next request on a separate api process.

## For the user to see
- **Built-in role contents are our reading of a one-line brief** (D61), for example Order manager holds the whole Orders area, including delete. The research lists permissions, not levels; "View" never grants a sensitive permission (D62).
- **Arabic labels need a native review.** French permission labels are deferred (D72).

## Not fixed, and why
- **Store switcher and "Administration" heading:** P1.S5, as before.
- **Activity log retention, partitioning and append-only:** later sessions (D65).
- **The first local evidence run on a loaded machine can fail** when a fresh Postgres stays unhealthy. The cause is unknown; a re-run passed.

## Notes for later sessions
- **Guards:** each feature plugin guards its handlers with `requirePermission('<area>.<action>')`. `test:arch` refuses an unguarded handler.
- **Activity log:** publish `ActivityRecordEvent` with the transactional context; the row joins that transaction (D66).
- **P1.S4:** calls `MemberAccessService`. `setAccess` inside an outer transaction flushes before that commit, so the caller must flush again after it (see its TSDoc). Merchants hold only stock `Authenticated`; `UpdateAdministrator` must stay ungranted without a shadow.
- **P1.S5:** reads the catalog and effective permissions for sidebar hiding; the switcher must show names and filter archived stores.
- **Adding to `ENGINE_GRANTS`:** the next migrate applies it to every role's bindings, custom ones too.
- **Businesses provisioned by an older instance after a converge** wait for the next migrate.
- **`convergeBusiness` takes a `ConvergeTarget`,** not a bare business id (deviation from the plan).
- **`@cod/plugin-tenancy/provisioning`** is restricted to `plugins/rbac/infrastructure` by an architecture rule.
