## Deviations (dated 2026-11-08, CLAUDE.md §3a.12)
- **Plan deviation 6 (tenancy stub):** one channel stands for one business. `ChannelTenantScopeResolver` returns `toBusinessId(String(ctx.channelId))`, and the platform default channel is also treated as a business until P1.S1. **P1.S1 replaces the three stubs** (`ChannelTenantScopeResolver`, `RequestTenantScope`, `NoteEntity`'s own `businessId`).
- **Plan deviation 7 (ids):** `RandomBigintIdGenerator`, a 63-bit random placeholder. **The ADR 0003 snowflake generator belongs to P1.S1.**
- **Note ids are `String!` in GraphQL, not ADR 0003's `ID!` (ruling P6-3).** Vendure's `IdInterceptor` decodes every `ID` argument with the entity id strategy; the default does `+id`, which loses digits of a 63-bit id. **P1.S1 decides** (a hybrid `EntityIdStrategy` with `ID!`, or `String!` with an ADR 0003 addendum).
- `index.ts` also exports the two dashboard constants that `apps/server/tests/browser/dashboard-pages.ts` needs (apps may import a plugin only through its entry point).
- `@cod/testing` has extra exports (the initial data, the DZD currency code, the default channel token). `toNoteId` and `InvalidNoteIdError` were added so a malformed id is a typed input error, not a database error.
- The server's `migrate-seed` and `migrate-concurrent` e2e tests count the committed migrations instead of assuming one.
- `@tanstack/react-query` is a direct dependency of the template dashboard, pinned to the version `@vendure/dashboard` resolves.
- **Vendure 3.8.1 has no route-level permission:** the nav item is hidden without `ReadTemplateNote`, but a direct URL still shows the error alert.
- **`pnpm-lock.yaml` has peer-hash churn** (the optional `@typescript-eslint/parser` peer; no version changed). `eslint-plugin-boundaries` now has two peer snapshots.
- **Screenshots are committed evidence** (ruling P6-2) in `docs/evidence/P0.S2b-6/`, not `docs/roadmap/assets/p0-s2b`.

## Gotchas
- **`@vendure/dashboard` types are TS source:** type-check plugin dashboards with `cod-typecheck-own` (the template's `typecheck` script does).
- **Vendure's default-allow:** a handler with no `@Allow` is open. Every endpoint needs its FORBIDDEN test (in the README checklist).
- **Vendure falls back to the default channel for a missing token** when only one channel exists: isolation tests must create two channels and reject an unknown token (RF1).
- **`.eslintcache` can show stale results** after a change to ESLint settings: delete it.
- **`setChannelToken(null)` sends the header `"null"`**, which fails with `CHANNEL_NOT_FOUND`; use `PLUGIN_TEST_DEFAULT_CHANNEL_TOKEN`.
