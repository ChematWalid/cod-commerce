## Deviations (dated 2026-11-08, CLAUDE.md §3a.12)
- **Plan deviation 12:** the dashboard stays at `/dashboard` in P0 (it moves to the root in P3.S5), and has no `.po` catalogues (P1.S5). The "Merchant shell" title and the stock "Administration" sidebar label are English in the Arabic screenshots.
- **`customProviders` accepted the children-wrapping component** (`{ id, component }` entries). No `toolbarItems` fallback was needed.
- **The dashboard typecheck uses `cod-typecheck-own`, not `tsc --noEmit -p dashboard/tsconfig.json`.**
  - `@vendure/dashboard` publishes its TypeScript source as its types (`"types": "./src/lib/index.ts"`). That source has about 143 errors under our strict base, and about 15 even with relaxed flags. `skipLibCheck` only skips `.d.ts` files.
  - The bin (`packages/config/typecheck/cod-typecheck-own.mts`) builds the program and reports every diagnostic outside `node_modules`, plus the global ones, so our code stays fully strict.
  - Tests spawn the bin and expect exit 1 on our own error and exit 0 on a dependency-only error.
  - Re-check it at the Vendure upgrade (M.S1).
- **Two `vendureDashboardPlugin` 3.8.1 quirks:**
  - it drops user `resolve.conditions`, so a small `enforce: 'post'` plugin re-adds `@cod/source`;
  - it misses the pnpm workspace plugin unless `pluginPackageScanner.nodeModulesRoot` is set.

  Both are upstream issue candidates.
- **More config:**
  - `apps/server/tests/browser/tsconfig.json` (DOM lib, kept out of the server program);
  - `apps/server/tsconfig.dashboard.json` (only the `paths`, which the Vite plugin reads);
  - `src/gql` (generated) excluded from the server build, typecheck, ESLint, Prettier and the image;
  - `vite build.emptyOutDir: true` (the plugin moves Vite's root, so stale assets piled up);
  - `vitest.browser.config.ts` with no SWC plugin (SWC's ES5 output broke `page.evaluate`).
- **Merchant-shell constants live in `dashboard/constants.ts`**, as the brief says. The plugin root re-exports the test-facing ones, so `apps/` imports only the entry point. As a result `dist/dashboard/constants.js` is emitted. Moving them to `domain/constants.ts` is a P1.S5 item.
- **`react` and `@types/react` are dependencies of merchant-shell**, because pnpm's strict layout resolves `react/jsx-runtime` from the plugin.
- **Screenshots are committed evidence** in `docs/evidence/P0.S2b-4/` (ruling P4-3), not `docs/roadmap/assets/p0-s2b`. Eight shots instead of the plan's two: login and shell, ar and en, desktop and mobile.
- **The Arabic login page comes from the persisted display language.** 3.8.1 has no language picker on the login page and ignores the browser locale; it reads the language persisted in `localStorage` (`vendure-user-settings`) by an earlier in-app switch. A first-time visitor sees English.
- **Placeholder `ARG`s for the dashboard build are visible in `docker history`.** They are the public `.env.example` values. Never pass real values; the Dockerfile comment says so.

## Gotchas
- **`@vendure/dashboard` types are TypeScript source.** Never type-check a dashboard tsconfig with plain `tsc`; use `cod-typecheck-own` (the merchant-shell `typecheck` script does).
- **The Vite plugin drops `resolve.conditions` and guesses the plugin root wrongly under pnpm.** Keep the post plugin and `nodeModulesRoot` in `vite.config.mts`.
- **`src/gql` is generated by `build:dashboard`** and git-ignored. Nothing may import `@/gql` until a session adds codegen to typecheck.
- **Turbo's `build` outputs exclude `dist/dashboard/**`.** Otherwise a cache hit restores a stale dashboard over a fresh `build:dashboard`.
- **The containerised api and a host-run api both use port 3100**: run one at a time.
- **On a phone-sized viewport the user menu is inside the collapsed sidebar.** The evidence signs in and switches language in a desktop context, then hands its storage state to the mobile context.
- **Clearing cookies does not sign out of the dashboard:** it keeps a session token in `localStorage`. Use the `logout` mutation.
