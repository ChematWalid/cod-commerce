# Handoff — P1.S4 rbac audit follow-up (`fix/s4-audit-rbac`)

Stacked on the P1.S4 core PR (#233). This is a separate file so it does not conflict with `P1.S4.md`, which lane 2 writes. The plan is `docs/roadmap/plans/P1.S4-audit-rbac-plan.md`.

## Done
- **#138 TEN-13 (remainder), D802:** `CreateTenantBusiness` and `DeleteTenantBusiness` are platform-only. No Owner role holds them; the superadmin does. Existing Owners lose them on the next `migrate` run, through converge (proved in `converge.int.test.ts`). `plugin-permissions-grantable.test.ts` no longer has a pending list, so it fails on any plugin permission only an Owner holds.
- **#162 RBAC-6, D800:** `sanitizeDiff` redacts every key that holds a D66 term or a P1.S3 extra term:
  - It checks the key in three forms: as typed, NFKD-decomposed, and character by character.
  - The term can sit anywhere in the key, in any case, and its words may be split by any punctuation.
  - The only exemption is a match lying wholly inside a benign word.
  - A key over 256 characters is redacted without being read.
  - Functions and invalid dates are stored as the omitted marker. A valid date is stored as its real ISO time. Arrays are copied as plain arrays.
- **#163 RBAC-7, D801:** `ENGINE_GRANTS` is reviewed per catalogue-key → permission pair, for stock and plugin permissions.
- **#164 RBAC-8:** a dated deviation note in `handoff/P1.S3.md` records that `templateOf` was never built.
- **Task 11 findings F1 to F5, D803:**
  - A resend judges the actor's privilege first, then the resend limit, the cooldown and, when it reopens an expired invitation, the pending cap (F1, F5).
  - Tests now pin the accept feature check (F2), the D205 headers on successful preview and accept (F3), and two-business preview isolation (F4).

- **Deactivate/remove racing `setMemberAccess` (lane 2 review), D804:** rbac's new `withdrawAccess` clears a member and returns what it held, under the rbac lock. Team's deactivate snapshots that result, and Team's remove always withdraws through it, so a concurrent grant can no longer survive a deactivate or remove, nor be lost from the snapshot. Proved by `plugins/team/tests/integration/deactivate-race.int.test.ts`: the interleaving is forced by running `setMemberAccess` inside Team's read. Unit tests: `deactivate-race.test.ts` (team) and `member-access-clear.test.ts` (rbac).

## For the user to see
- D802 removes two permissions from every Owner role at the next `migrate` run. No handler used them.
- D800 fails closed: a harmless key that happens to contain a term, such as `hotpot` or `accessKeyboard`, shows `[REDACTED]` in the activity log.

## Not fixed, and why
- Look-alike letters from other scripts, such as Cyrillic `о` in `tоken`, are not redacted. No Unicode normalisation maps them to ASCII. This is out of D800's scope.
- `sanitizeDiff` accepts a non-object at the top level without throwing. Every caller is typed, so this is low risk.

## Notes for later sessions
- A new `ENGINE_GRANTS` entry needs a matching entry in `REVIEWED_PLUGIN_ENGINE_GRANTS` or `REVIEWED_STOCK_ENGINE_GRANTS` (D801).
- A self-service "delete my business" feature needs its own catalogue key and review. Do not reuse `DeleteTenantBusiness` (D802).
