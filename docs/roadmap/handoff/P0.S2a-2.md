## Deviations
- **New machine.** Arch Linux with native Docker instead of Windows with Docker Desktop. The `.wslconfig` step was dropped. Different host ports: Valkey 6380, API 3100, because unrelated local containers hold 3000, 6379 and 8080. Node 24.22.1 via mise (host Node is 26).
- **Postgres data on the SSD via a bind mount**, not a named volume. Docker's root on this machine is a 7 200 rpm HDD; one HDD cold trial cost 1 570 ms for a 20-product list (recorded in ADR 0002 Evidence). All reported cold numbers are SSD.
- **DB time via `pg_stat_statements`**, not pgbench scripts. Each case is the real multi-statement set Vendure issues on any store, so per-statement replay with ID rewriting wasn't needed. Same cold/warm protocol.
- **Steady-state session fix.** The first cold run included the session read and update of the first request after login (+24 ms). The product list was re-run with the fix (167.9 ms → 46.3 ms p95). Product detail and the random-store order list were not re-run; they already pass with the extra cost included.

- **End-of-session clean re-run:** D = `SHOW CONFIG` plus the quiet scheduler window (fresh processes); C = one cold (c) on the existing seeded DB (6.4 ms). Re-seeding does not fit in the time.

## Gotchas
- **Shell:** this machine's zsh aliases `sed`, `cut`, `tr`, `grep`, `cat` and `ls` to other tools (`tr` = a translator). Use `command X`, or put checks in a `bash` script. Never `pkill -f`/`kill $(pgrep -f …)` with a pattern that occurs in your own command line: it kills the tool's shell.
- **PgBouncer `KILL <db>` pauses that database** until `RESUME <db>`; new connections hang.
- **`@vendure/testing`'s Postgres initializer cannot drop the test DB through PgBouncer**; point test DB setup at Postgres directly.
- **Concurrent first boot fails** (`__default_channel__` duplicate): seed with one process first.
- `GlobalSettings.availableLanguages` must include `ar` before creating `ar` channels.
- Vendure's per-request log of TypeORM queries needs `logger: new DefaultLogger({ level: LogLevel.Debug })` **and** `dbConnectionOptions.logging: ['query']`.
- The 3.8.1 channel cache is a lazy per-token `Map`, not an all-channels list.
- `pgbench` scripts are not needed: `pg_stat_statements_reset()` + one API call + `sum(total_exec_time)` gives exact DB time per request.
