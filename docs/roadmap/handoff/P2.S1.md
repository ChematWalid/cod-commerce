## Gotchas
- The template plugin registers only with `APP_ENV` development or test; the P1 isolation e2e and `scripts/evidence/P1-isolation.sh` need one of them for the template note rows.
- Arabic slugs are stored NFD (Vendure `normalizeString`); compare slugs through the catalog's slug functions, never by raw string.
- Variants are created with `trackInventory: 'FALSE'` (store channels have no stock location).
- CI part `catalog` runs the catalog integration tests (`.github/workflows/ci.yml`, `EXPECTED_MATRIX_PARTS`).
- Ids handed to Vendure inside inputs must be engine integers (`engineIdOf`, D2159).
- Any new catalog operation or route must be added to the plugin registry and to `apps/server/tests/isolation/catalog-operations.ts` (or the sold-out/type files beside it), or `p2-isolation-matrix.test.ts` fails.
- Integration snowflake worker ids must stay in 1000-1023; catalog uses 1020-1023.
- A product create that sends `settings` must send the full object (every flag and `quantityRules`); a patch may send part of it.
- Dashboard gates: `#` plus 3/4/6/8 hex digits anywhere in a dashboard file (comments too) reads as a colour (write audit ids without `#`); palette classes are refused (use theme tokens); a constant named `*_TITLE` or `*_MESSAGE_ID`, and any `title: ''`, is scanned as a catalogue id; every new dotted literal in dashboard code is a catalogue id unless it is a permission key or declared in `NON_MESSAGE_LITERALS`.
- REST handlers run as Vendure's shop API: list calls cap at 100 (D2167, #248).
- `build:dashboard` locally needs every workspace `dist` built (`pnpm --filter "@cod/server^..." build`) and the env block of the CI job "Build the dashboard".
- The main checkout's `apps/server/.env` lacks variables newer than 2026-11-11 (`TENANT_SECRET_KEKS`, `TENANT_SECRET_ACTIVE_KID`, `AUTH_TOKEN_SECRET`, …): `pnpm --filter @cod/server migrate` fails `loadEnv` with it alone. The user adds real values; agents do not mint them. The evidence script falls back to synthetic defaults.
- The demo seed's server wiring (first store, language, scope) is exercised only by the `browser.yml` seed steps.
