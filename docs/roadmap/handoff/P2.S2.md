## Gotchas
- **`S3_PUBLIC_ENDPOINT` and CORS:** the browser cannot reach `garage:3900`. Set `S3_PUBLIC_ENDPOINT` (for example `http://localhost:3900`, commented in `.env.example`; blank in compose because of the portability gate), and run `node scripts/garage-cors.mjs` once after `docker compose up` so the dashboard origin may PUT/GET. `scripts/check-data-services.sh`, `browser.yml` and the evidence script already run it.
- **`LINK_IMPORT_SCRAPER`:** `fixture` (only host `shop.example.test`) for tests, the evidence and local demos; the default is `http`. Boot refuses `fixture` when `APP_ENV=production`, and refuses the memory object storage there too.
- **`QUOTE_HMAC_KEYS` / `QUOTE_HMAC_ACTIVE_KID`** must be in the environment for the catalog-packs integration tests (`packs-kit.ts` boots `OffersPlugin`), not only for the server. Copy them from `.env.example` into the worktree's `.env`. They are listed in `turbo.json` `passThroughEnv`.
- **Worker ids:** catalog-packs integration 1016, catalog-import 1017.
- **Evidence retry loop:** `scripts/evidence/P2.S2-api.sh` still retries the 520-row import up to 4 times (`JOB_IMPORT_MAX_ATTEMPTS=4`, lines 10 and 234–238), a workaround for #260. With D2282 it can be removed, but that needs an evidence rerun on a new image, so the loop stays for now (#270 item 18). The last run needed 1 attempt.
- Memory object storage in CI is reached through the DI token (`app.get(CATALOG_IMPORT_OBJECT_STORAGE)`); nothing serves its `memory://` URLs.
- Bulk-edit tag add/remove is last writer wins between two concurrent bulk edits of the same product (D2213).
- An imported product publishes two `product.changed` events (D2219); consumers are idempotent.
- Pass Vendure ids as integers (`rawTestId`) to SQL and to `quoteForScope`; GraphQL wire ids (`T_n`) are not row ids.
