## For the user to see (product decisions, pre-approved, please review)
- **D2302 + D2339: Manual and Automatic are exclusive.** Switching manual → automatic asks for confirmation, because the hand-picked list is discarded.
- **D2303 operators:**
  - tag and brand: "is any of" / "is not";
  - price: "between", inclusive;
  - on sale: yes/no;
  - title: "contains" / "does not contain";
  - option values: "is any of".
  - `is not [a, b]` means *neither* a nor b.
- **D2304 price:** a product's price is its lowest visible variant price. "On sale" means any visible variant has an old price above its price. Example: variants at 800 and 3 000 DZD fall in a 500–1 000 rule.
- **D2305 letter folding:** title and option matching ignores case, Arabic harakat and tatweel, and folds أ/إ/آ→ا, ى→ي, ة→ه.
- **D2306 membership ignores status:** drafts, hidden and sold-out products are members; the buyer-facing read hides them.
- **D2309:** a product's own `collectionIds` are manual collections only.
- **D2320:** setting a collection image needs the product-media keys.
- **D2325 list columns:** image and title, type, products, visibility, position.
- **D2326:** the Arabic term is "المجموعات"; a native review is pending (#268).

## Notes for later sessions
- **Import surface** (`@cod/plugin-collections-rules`, only from `infrastructure/`, `*.plugin.ts` or tests; rule `collections-entry-infra-only`):
  - `CollectionsReadService` (buyer-facing): `listVisible(ctx, { skip, take })`, `productsOf(ctx, collectionId, context, page)`;
  - `CollectionMembershipQueries` (merchant-level, includes hidden collections and draft products): `productIdsOf` (unbounded), `collectionIdsOfProducts` (one query for a cart), `isMember`, `existingCollectionIds`. Every call takes a `StoreScope` from the context, never from request input.
- **Events:**
  - every product writer must publish `product.changed`;
  - listen to `collection.changed` to revalidate collection pages (P3.S2);
  - membership lags product edits by the outbox delay (seconds).
- **Offers editor:** the collection picker (D2523) is still disabled. The API now accepts and checks collection targets, so enabling the picker is a dashboard-only follow-up in the offers lane (noted on #273).
- **Live collections:** a collection counts as live when it has a `collections_definition` row. A Vendure collection made outside collections-rules (the stock `createCollection` is FORBIDDEN today) would be refused as an offer target.

## Gotchas
- **Stock filters:** `CollectionFilter`s are switched off globally (D2301). Never re-enable Vendure's collection recompute: it would fight our tables.
- **Default channel:** `CollectionService.create` also joins the default channel, so our adapter removes it in the same transaction (D2333).
- **Lock order:** catalog takes its product row lock, then the store lock. Nothing that holds the store lock may take a product lock.
- **Consumer context:** the business comes from the delivery scope; the store must be an active store of that business (`StoreChannelContexts.forStore`).
- **Migration:** a phase merge that brings a newer migration means re-timestamping file, class and `name` (D2329). The evidence script uses fresh volumes, but a long-lived dev database that ran the old name needs `docker compose down -v` or a manual rename in `migrations`.
- **Registered catalog source:** it refuses collections without a definition (`catalog.collection-not-found`).
- **Evidence script:** it refuses to run with uncommitted changes outside the evidence folders, and `docker compose down -v` wipes the project's volumes.
- **RTL tables:** stock table cells align to a physical side; put `text-start` on header **and** value cells.
