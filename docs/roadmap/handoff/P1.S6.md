# Handoff — P1.S6 (Platform plumbing: queues, outbox, webhooks, secrets, flags)

## Done
1. **Queue registry and pools** (D99-D101, D100 settles the ADR 0013 addendum, option c): `packages/shared/src/queues.ts` holds every ADR 0013 queue with its pool, attempts, backoff and concurrency; `plugins/platform-jobs` routes each queue to one stock BullMQ strategy per pool (prefix `bull:{APP_ENV}:{pool}`). `WORKER_POOL=critical|bulk|all` (default `all`) replaces `WORKER_ACTIVE_QUEUES`, which boot refuses when non-empty. Jobs carry ids `{pool}.{bullId}`. Also in `platform-jobs`: durable job ids (D102), the business semaphore and circuit breaker on Valkey (D103), continuation jobs, `catchUpTask` with a task heartbeat (D120), and the job reconciler (D105, D125, D129).
2. **Native partitions** (D106, D107): `plugins/platform-partitions` creates premade daily or monthly range partitions (no `DEFAULT`), drops expired ones unless a `keepIf` keeps them, and scrubs payloads by age; per table, partitions are created in their own transaction, then drop and scrub run in a second one, each with `SET LOCAL lock_timeout` and a transaction-scoped advisory lock. The migrate role runs maintenance once; `partition-maintenance` runs daily at 02:00 UTC.
3. **Transactional outbox** (D104, D105, D124, D125, D130): `OutboxService.add` inside the caller's transaction, a relay job that writes the deliveries and marks `relayed`, consumers on registry queues with exactly-once database effects, the sweeper (pending rows older than 60 s, clearing a settled relay job first), the reconciler (missing, settled, stuck and exhausted jobs), and the staff query `platformJobsHealth`.
4. **Internal HMAC guard** (D111-D113, ADR 0008 addendum): `@cod/shared` signs and verifies `cod-internal-v1` requests; a `beforeListen` middleware guards `/shop-api`, `/store` and `/_internal` on every host and answers 404 with an empty body on any failure except an oversized body (413 above 100 KB). The storefront's `internalFetch` signs every API call (D126).
5. **Tenant secrets and KEK rotation** (D114, D115, D127, D130): `tenant_data_key` and `tenant_secret`, AES-256-GCM envelopes with the business and ref in the AAD, GraphQL `setTenantSecret`, `tenantSecrets` (`last4` only), `deleteTenantSecret` behind `apps.manage`/`apps.view`; the daily `tenant-secret-kek-rotation` task re-wraps one business per job and reports how many keys remain on retired kids.
6. **Inbound webhook gateway** (D109, D110): `POST /webhooks/:provider/:accountKey`, raw bytes up to 256 KiB, kill switch, dedupe on `inbound_webhook_key`, the payload in partitioned `inbound_webhook`, processing as `iw-{id}` jobs, a 30-day key purge. The demo handler (provider `demo`, consumer `demo-log`) runs only with `PLATFORM_DEMO_HANDLERS=true`, which production refuses.
7. **Flags and kill switches** (D116, D117, D128): `feature_flag` and `feature_flag_override` with store > business > plan > default precedence and a hashed rollout, a process snapshot behind a Valkey snapshot with pub/sub invalidation that keeps working when Valkey is down; four seeds (`intake.spool.enabled`, `inbound-webhooks.enabled`, `ai.enabled`, `capi.enabled`). The staff screen `/platform/flags` (PlatformStaff only) lists flags, edits default and rollout, and adds or removes overrides, in Arabic and English.
8. **`activity_log`** (D123, audit RBAC-2 #113, partly): monthly partitions, 24-month retention, append-only by a `BEFORE UPDATE OR DELETE` trigger. A 24-month-old partition is kept until an archive exists.
9. **Migrate role hardening** (D122, audit SRV-2 #115, SRV-12 #191, SRV-13 #192): `lock_timeout` 5 s, `statement_timeout` 15 min, a 10-minute bounded wait on the migrate lock that names the holder, no scheduler tasks in the migrate config.
10. **CI parts** (D118): the integration matrix runs `others`, `server-e2e`, `tenancy-1/2`, `auth-1/2`, `rbac-1/2`, `platform-1` (jobs, partitions, outbox) and `platform-2` (secrets, webhooks, flags); `browser.yml` caches the Playwright browser (D119).
11. **Schema drift checks** (audit SRV-7 #186): `partitioned-schema.e2e.test.ts` compares the migrated database with each `*_SCHEMAS` constant and the entities, `migrations-roundtrip.e2e.test.ts` reverts every migration and migrates up again to the same catalog snapshot, and `migrate-seed.e2e.test.ts` stays the TypeORM drift check (ADR 0016 "As implemented").
12. **Evidence:** `docs/evidence/P1.S6/` from `scripts/evidence/P1.S6.sh` (6 API transcripts, 8 screenshots).

## Gotchas
- **Local `.env` files must add** `INTERNAL_HMAC_KEYS`, `INTERNAL_HMAC_ACTIVE_KID`, `TENANT_SECRET_KEKS` and `TENANT_SECRET_ACTIVE_KID` (and the storefront's `INTERNAL_HMAC_KEYS`, `INTERNAL_HMAC_ACTIVE_KID`); `INTERNAL_HMAC_SECRET` is gone. The user adds them; values are never committed (`.env.example` has placeholders).
- `pnpm lint` now runs with a 6 GB heap (`package.json`).
- The `test:arch` lint tests can time out at their 5 s limit under load on a shared machine; they pass alone. Watch them in CI.
- Run integration tests per package: one whole `turbo run test:integration` takes more than 30 minutes locally.
- Main brought D309: host cache keys are now `host:<namespace>:<host>` (namespace = `APP_ENV`); anything that reads or clears `host:<host>` must use the namespaced key.
- Unsigned calls to `/shop-api`, `/store/*` and `/_internal` now get an empty 404 from the full server config. Tests and scripts must sign them (`@cod/shared/internal-auth`, or `scripts/evidence/lib/sign.sh`).
- Durable job ids must not end in `-r<digits>` (that shape is a continuation); KEK ids are refused in that shape too.

## Notes for later sessions
- **Queue:** add an entry to `packages/shared/src/queues.ts` (pool, attempts, backoff, concurrency), then `define` it and `add` jobs through `PlatformQueues` in your plugin. A name outside the registry throws. Durable ids come from `durableJobId()`.
- **Outbox topic and consumer:** add the topic to `packages/shared/src/outbox/topics.ts`; call `OutboxService.add(scope, …)` inside the transaction that changes the data; register an `OutboxConsumer` with `OutboxConsumerRegistry.register` in `onModuleInit`. Consumers must be idempotent; use the `{outboxId}:{consumer}` key for external effects and `OutboxParkError` to park.
- **Inbound handler:** implement `InboundWebhookHandler` (`provider`, `persistedHeaders`, `resolveAccount`, `verify`, `eventKey` (null for the default raw-body key), `process`) and register it with `InboundWebhookHandlerRegistry.register`. The demo handler in `plugins/platform-webhooks/infrastructure/demo/` is the model.
- **Partition policy:** a `PartitionedTableSchema` constant in the owning plugin, a migration with its SQL copied literally, `PartitionRegistry.register(policy)` with table, column, interval, premake, retain, optional `keepIf` and `scrub`; the drift e2e checks the copy.
- **Reconcile source:** implement `ReconcileSource` and call `JobReconciler.registerSource`.
- **Tenant secret provider:** register a `TenantSecretProvider` with `TenantSecretProviderRegistry.register`; read with `TenantSecretService.reveal(scope, provider, ref)`, never log the value.
- **Flag seed:** add to `FLAG_KEYS` and `FLAG_SEEDS` in `packages/shared/src/flags/flag-keys.ts`; the migrate role seeds it and never overwrites a staff change. Read flags with `FeatureFlags`.
- **`WORKER_POOL`:** compose keeps one worker on `all`; split into `critical` and `bulk` processes later. Drain a worker before switching prefix.
- **Rotate the internal HMAC key:** add the new `kid:secret` to the api's `INTERNAL_HMAC_KEYS`, deploy, switch the storefront's `INTERNAL_HMAC_ACTIVE_KID` (and keys) to it, deploy, then remove the old key from the api.
- **Rotate a KEK:** add it to `TENANT_SECRET_KEKS`, switch `TENANT_SECRET_ACTIVE_KID`, let `tenant-secret-kek-rotation` run (or run it) until it reports zero remaining, then remove the old KEK.
- Trust of `x-client-ip` and `x-client-country` on signed requests (no Turnstile yet) is P3.S4's.
- The demo handler must stay off in production.
