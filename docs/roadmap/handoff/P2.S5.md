- **Product decisions to review:**
  - **D2503:** a BXGY gift in `fixed` mode is an **amount off** each gift unit (like product discount's `fixed`), not a fixed gift price.
  - **D2504:** the **cheapest** matched units are gifted; **gift units count** in quantity-tier pieces and the subtotal; a gift is removed only by lowering the paid quantity (no way to decline only the gift: a later `QuoteRequest.declinedGifts?: offerId[]` would add it).
  - **D2507:** add-ons always combine and **count toward order minimums** and order discounts.
  - **D2510:** live offers are re-validated on update and resume (a live edit that breaks a publish rule is refused).
  - **D2521:** **only drafts can be deleted**; a published offer is archived so orders and stats keep its id.
  - **D2516:** the preview **ignores audience and schedule** (and limits); the summary states them.
  - **D2449 / D2512:** codes exist **only on code offers**; a generated batch is all-or-none.

## Gotchas
- **Drafts only go live through `publish`:** `setStatus(…, 'active')` on a draft is refused (`offers.invalid-transition`); tests and scripts that activated a draft use `publish` (D2510).
- **A blank title is `offers.invalid-config`** (input schema), never `publish-invalid` `title` (D2533 (i)).
- **Publish refuses an end date already past:** an evidence offer that must expire ends seconds after its own creation and the run waits (D2533 (f)).
- **Generated code prefixes are upper case** (`[A-Z0-9]{0,8}`); a lower-case prefix answers 400 (the dashboard upper-cases it).
- **GraphQL ids are `String`:** strip the test id strategy's `T_` prefix from catalog ids before naming them as targets (D2535 (a)).
- **Offers integration worker ids 974–979** are taken (plus P2.S4's 990–994).
- The browser spec runs only in the `browser` workflow on `phase/P2` pushes, not on the PR.
