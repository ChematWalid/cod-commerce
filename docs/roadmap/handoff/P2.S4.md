## Decisions
D2400–D2434 were taken in planning (see `P2-decisions.md`). Taken during the work:
- **D2435** per-buyer limited offer skipped `per_buyer_limit` when the quote has no phone.
- **D2436** nudge saving on mixed prices uses the smallest next-tier discount for the missing pieces.
- **D2437** candidates ranked on the cart before offers, accepted ones re-evaluated in stage order.
- **D2438** overlaps: order discounts clamped to what the subtotal still has, a delivery waived once, nudge on pre-offer cart, `p` set only by an applied phone-dependent offer.
- **D2439** store-owned rows: `storeId NOT NULL` as named checks `CHK_offers_*_store`.
- **D2440** offer lifecycle (draft → active/archived, …), `publishedAt` set once, patch edits, optimistic lock.
- **D2441** `UnitPriceResolver` port matches P2.S2's `PackUnitPriceResolver`.
- **D2442** reprice keeps the audience fixed at intake (`OrderUsage.buyerOrdersBefore`).
- **D2443** repository contract tests await a refused write where it starts (`rejectionOf`, `withRoundTrips`).
- **D2444** the `PricingSnapshotSource` port is real; P3.S3 rebinds it to a cache; code writes do not bump the offer `version`.
- **D2445** the token signs `o` (every applied offer with its code), stored on the order as `appliedOffers`.
- **D2446** an order change is measured from the stored total: `storedTotal` required, `delta = after.total − storedTotal`, `drift = before.total − storedTotal`.
- **D2447** `OfferUsageService` owns the use-count writes (guarded `UPDATE`s).
- **D2448** admin and usage use cases check the scope's store channel (an archived store's own channel is accepted for usage).
- **D2449** codes only on offers whose method is `codes`.
- **D2450** an active offer with a stored config its kind no longer accepts is left out of the snapshot and logged once.
- **D2451** the held-offers bound counts the delivery waiver (209).

## For the user to see
- **ADR 0004 amendments to accept:**
  - **D2421 token** (recorded in the decision log; the ADR text was not edited for these): `h` also covers `channel`; the phone enters `h` for audience **or per-buyer limit** offers (not only eligibility); a signed flag `p: 0|1` says whether `h` includes the phone; the phone enters `h` as an HMAC with the kid's key, not a bare SHA-256.
  - **D2445 `o` claim** (edited in `docs/adr/0004-pricing-engine-and-order-totals.md` in this branch): the token lists every applied offer `[{ offerId, code? }]`, stored on the order as `appliedOffers`.
  - **D2446 reprice** (edited in ADR 0004 in this branch): an edit re-prices every line of the changed cart at today's snapshot and its delta is measured from the order's stored total.
- **Product decisions to review:**
  - **D2414:** free delivery waives the base fee **and** the overweight fee (ADR 0004, brief AC1). The research hints the reference may still charge overweight; confirm, or amend ADR 0004 to charge it (one line in `domain/engine/delivery.ts`).
  - **D2409:** total-price mode gives every matched unit `min(original, roundHalfUp(tierTotal / tierQuantity))`; a non-divisible tier total is off by < 1 DZD per unit (P2.S5's editor should warn).
  - **D2411:** combination ranks candidates by buyer saving, then offer id; a loser is skipped `not_combinable`.
  - **D2416:** the nudge covers quantity tiers only and states the saving at the next tier without delivery.
  - **D2418:** until P3.S4 registers buyer history, every phone counts as a first-time buyer.
  - **D2449:** codes can only be added to offers activated by codes.
  - **Assumed 15 % 3-piece tier:** the research fixture's tier 3 (15 % + free delivery) is an assumption; the research elides it.

## Gotchas
- **Copy the two `QUOTE_HMAC_*` lines** (`QUOTE_HMAC_KEYS`, `QUOTE_HMAC_ACTIVE_KID`) from `.env.example` into every local `.env` (root and `apps/server/.env`), or `loadEnv()` fails and the dev stack stops booting. The placeholder is rejected when deployed: the user sets real keys.
