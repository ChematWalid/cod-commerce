# Handoff — P0.S2b-2 Server core (typed env, health probes, Vendure config per role)

**State:** done. Branch `feat/p0-s2b2-server-core`, issue #79. Plan: [`plans/P0.S2b-plan.md`](../plans/P0.S2b-plan.md), Part 2, Tasks 5–8. It was executed subagent-driven: a fresh implementer per task, a task review per task, then a final whole-branch review and one fix wave.

**The server cannot boot yet.** There are no entry points (`main.ts`, worker, `migrate`), no migrations and no image: those arrive in Part 3 (Tasks 9–12). Everything here is proven by unit and integration tests, not by a running server.

## Done

**Task 5: `apps/server` and the typed env.** Commit `873dc9c`.
- `@cod/server`: package, tsconfigs, Vitest projects `unit` and `e2e` (`tests/setup-env.ts` loads `apps/server/.env` if present), `.env.example` for host-run dev (`API_PORT=3100`).
- `src/config/env.ts`: `loadEnv()` validates every variable with zod 4 and fails fast with `EnvValidationError`, whose message is built from the variable name and the rule only, never from the value.
  - Role defaults: `DB_POOL_MAX` api 10, worker 5, migrate 2; ports 3000 / 3020; S3 region `garage`, path-style `true`.
  - **RF5:** both database URLs must pass `toPostgresFields`, so a reserved character in a password is rejected instead of silently changing the host.
  - **M4:** in `staging` and `production`, placeholder secrets (the `change-me` marker, or an all-zero hex value) are rejected for the cookie secret, the superadmin password, the S3 keys and both database passwords.
- `src/config/ports.ts`: `DEFAULT_API_PORT`, `DEFAULT_WORKER_HEALTH_PORT`, `DEV_API_PORT`.
- `@cod/shared` `platform/database-url.ts`: `toPostgresFields`, `PostgresFields`, `InvalidDatabaseUrlError`.
- The dependency-cruiser roots now include `apps`, with a new rule `apps-no-plugin-internals` (apps may import a plugin only through its entry point), a bad fixture and a test.

**Task 6: `plugins/platform-health`.** Commit `11a2faf`.
- `/livez` (event-loop lag ≤ 1000 ms) and `/readyz` (Postgres 500 ms, Redis 200 ms, migrations 2000 ms, run in parallel, each with its own timeout) as a Nest middleware on the api port; the same checks on a `node:http` server on port 3020 that only the worker role starts.
- §3a layout: framework-free `domain/` (readiness evaluation, `withTimeout`, ports, constants), `application/` services, `infrastructure/` probes and the worker server, `api/` response mapping and middleware.
- `@cod/shared` `platform/health.ts`: `HealthCheckResult`, `HealthProbeResponse`.
- `@cod/config/vitest/vendure`: `vendurePreset` (SWC with decorator metadata, forks pool, no file parallelism, 120 s timeouts).

**Task 7: Vendure config builder per role.** Commit `43dc217`.
- `buildVendureConfig(env, role)` composes one small builder per concern: db, redis/BullMQ, auth, job queue, plugins, `DzdMoneyStrategy`.
- api and worker connect through PgBouncer (`DATABASE_URL`); `migrate` connects directly (ADR 0016). `synchronize: false`; migrations glob `src|dist/migrations/*`.
- BullMQ on Valkey with `maxRetriesPerRequest: null` and the `bull:${APP_ENV}` prefix (ADR 0013); `activeQueues` only for the worker.
- `buildPlugins(env, role)` is the single registration point: BullMQ, RedisCache, DefaultScheduler and PlatformHealth for every role (so `migrate` creates every table, B1), Harden only for the api.
- Auth: `tokenMethod: ['cookie','bearer']` (ADR 0008). Money precision 0 (ADR 0004).

**Final fix wave.** Commits `389700f`, `35e9c10`, `4576df9`:
- the Vendure cache (which also holds sessions) is namespaced per environment: `vendure-cache:${APP_ENV}`. Before, two environments sharing a Valkey would have accepted each other's session tokens;
- the migrations probe is read-only: it selects the executed names from the migrations table and compares them with the configured migrations. TypeORM's `showMigrations()` created the table through PgBouncer and could leak a pooled connection;
- an unreachable Valkey at boot is logged and boot continues, so `/readyz` reports it. A policy that is read and is not `noeviction` still fails boot; the guard has a 2 s timeout; until the policy has been verified once, the Redis probe verifies it before reporting ok. CONFIG refused (`ERR unknown command`/`NOPERM`) fails closed with a typed error;
- `toPostgresFields` rejects a query string or fragment (a dropped `?sslmode=require` would silently downgrade TLS);
- `REDIS_URL` is fully validated by `loadEnv` (one shared parser, `redis-url.ts`).

**Task 8: CI.** Commit `d347997`: an `integration` job with Postgres and Valkey service containers (the same images and digests as `docker-compose.yml`, pinned equal by a test), placeholder env only, running `pnpm test:integration`; `build-test` now needs it.

## Deviations (dated 2026-11-07, CLAUDE.md §3a.12)
- **Plan deviation 9:** `@vendure/telemetry-plugin` is not registered (observability session). SIGTERM draining and the "draining"/"BullMQ connected" readiness checks are deferred to P3.S5.
- **Plan deviation 10:** `DzdMoneyStrategy` lives in `apps/server/src/config/` until P2.S4.
- **Plan deviation 16:** `@cod/shared` gained `platform/database-url.ts` and `platform/health.ts`.
- **`vendurePreset` drops the `module` condition** from `ssr.resolve.conditions` (the plan's Conventions say "defaults appended"). With `module`, `@vendure/core` fails to load under Vitest (`i18next-fs-backend`, `ERR_REQUIRE_ASYNC_MODULE`). `@cod/source` stays first in both lists; a test pins it. `unitPreset` is unchanged.
- **`@nestjs/common@12.4.0`** is a dependency of the plugin although it is not in the pin table: it is the exact version `@vendure/core` 3.8.1 resolves.
- **Test scripts use `vitest run --configLoader runner`**, which removes Node's `MODULE_TYPELESS_PACKAGE_JSON` warning on every run.
- **Env additions the brief did not specify:** a blank value (`KEY=`) counts as unset, so it falls back to the default; `LOG_LEVEL` accepts only Vendure's five levels.
- **Vendure config additions:** `cors: { origin: CORS_ORIGINS, credentials: true }` (cookie auth needs credentials), an empty `paymentOptions` (required by Vendure), and `healthChecks: []` kept although it is deprecated in 3.8.1.

## Follow-ups
- **Part 3 (Tasks 9–10):**
  - `buildVendureConfig(loadEnv(), 'migrate')` with `ROLE=api` sizes the pool as api (10): set `ROLE=migrate` for the migrate entry point and the generator, or size from the `role` argument.
  - The e2e must prove: `HealthMiddleware` answers on the api port before the AuthGuard; the worker starts its health server on 3020 under `bootstrapWorker`; booting with `redisUrl: redis://127.0.0.1:1` gives `/readyz` 503 (rulings 7).
  - A missing migrations table counts as "pending" even when there are no migrations; `migrate` creates the table on its first run.
- **P3.S5 (before the api is public):**
  - `/readyz` returns raw error text (for example `connect ECONNREFUSED host:port`): redact it and throttle the endpoint, since ADR 0012's load balancer and ADR 0015's external pinger make it public and every call hits Postgres and Redis.
  - `trustProxy: 1` assumes one proxy hop; ADR 0012's path (Cloudflare → load balancer → kamal-proxy) has more.
  - The `RedisCachePlugin` client keeps ioredis defaults (offline queue, 20 retries), so session lookups stall about 10 s while Valkey is down. Handle it with the ADR 0006 D4 cache rules.
- **Part 4 (dashboard):** `CORS_ORIGINS` defaults to `[]`, which denies every cross-origin request; the Vite dev server on 5173 may need it in `.env.example`.
- **Part 6 (`_template`):** `apps-no-plugin-internals` matches only layer folders, so `plugins/x/x.plugin.ts` imported directly would pass.
- **Minor hardening (triaged "can wait" by the final review):**
  - env: the placeholder check only runs when every field is valid (zod skips the object refine), so the TSDoc "listing every invalid variable" overstates; `rejectPlaceholders` re-parses the database URLs; `PLACEHOLDER_FORBIDDEN_ENVS` is typed `string[]`; `DB_POOL_MAX` has no upper bound; `apps/server` relies on the root `@types/node`;
  - tests: no cases yet for a bad `API_PORT`/`DB_POOL_MAX`/`S3_FORCE_PATH_STYLE`/`CORS_ORIGINS`, for the blank-value rule, or for the database-URL rejection branches (empty host, user, password, bad port, bad name); IPv6 hosts keep their brackets;
  - `redisOptionsFromUrl` ignores a query string or fragment on `REDIS_URL`;
  - platform-health: `evaluateReadiness` lists the probe names instead of deriving them from `PROBE_NAMES`; the worker server repeats the status mapping instead of `toHealthResponse`; `EventLoopLagMonitor.sample()` resets the histogram, so several callers interfere; the worker health server listens on all interfaces; `verifyAtBoot` downgrades any unexpected error to a warning (logged); a CONFIG refusal with another reply is untyped; the migrations probe ignores a `schema` option (none is set); the integration tests use a `pg` Pool rather than `TransactionalConnection`, and `HealthMiddleware`'s async `use()` has no catch (it cannot reject today);
  - config tests: the worker-health test reads the static `PlatformHealthPlugin.options`; `plugins.config.ts` import order.
- **From Part 1, still open:** the MinIO → Garage wording in the architecture docs; pin `attribution.yml` by SHA; a pnpm `catalog:` for the pins `packages/config` duplicates.

## Gotchas
- **Two copies of `@vendure/core`** break the plugin's `TransactionalConnection` injection at boot. After changing Vendure dependencies, check that `pnpm-lock.yaml` has one `@vendure/core@3.8.1` snapshot (`pnpm install --frozen-lockfile` fixed a transient duplicate).
- **Tests that import `@vendure/core` must use `vendurePreset`**, not `unitPreset` (the `module` condition, see Deviations).
- **CI has no `apps/server/.env`:** every variable `loadEnv` and the integration tests need is in the `integration` job's env. Valkey's default policy is already `noeviction`; service containers cannot take a `command:`.
- The command prelude, pnpm, memory and zsh notes from [`P0.S2b-1.md`](P0.S2b-1.md) still apply.
