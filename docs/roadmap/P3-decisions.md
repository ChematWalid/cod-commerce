# P3 decisions

Decisions taken while building phase P3. Each row gives the decision, why, and the cost if it proves wrong. Blocks: coordinator D3000–D3099, P3.S1 D3100–D3199, P3.S2 D3200–D3299, P3.S3 D3300–D3399, P3.S4 D3400–D3499, P3.S5 D3500–D3599.

## P3.S2

| # | Decision | Why | Cost if wrong |
|---|---|---|---|
| D3200 | P3.S2 runs as one session (no a/b split). Work is executed in waves of parallel tasks (plan "Execution waves"). | P3.S3 needs the store context, catalog endpoints and page shells together; the research gaps fit one plan. | A late split with a handoff at a clean commit. |
| D3201 | Tenancy owns the public tenant context: `StorefrontStoreGuard` + `@StorefrontCtx()` exported from `@cod/plugin-tenancy`, keyed by the HMAC-verified `req.internalAuth.storeId` (D111), building a store-channel `RequestContext` and remembering the tenant internally (`rememberTenant` stays private). **Deviation:** the brief lists only storefront files as owned; tenancy and rate-limit are touched with reviewed exports. | `CatalogReadService` / `CollectionsReadService` need `findTenant(ctx)` and the store channel; only tenancy may set the tenant (ADR 0002). | Two exports to move if a later session re-homes them. |
| D3202 | #209: the proxy rewrites to `/_t/{locale}/{storeId}/{binding}…` (locale first so `app/%5Ft/[locale]/layout.tsx` is a root layout with `<html lang dir>`), where `binding` is an HMAC of `(storeId, normalised host)` under keys derived from each configured internal HMAC key (`'storefront-host-binding-v1'`, no new secret). The tenant layout checks the binding against the store's `primaryHost`; every data loader needs the verified token, so a mismatch renders no store data (a soft 404 with status 200 under Cache Components, `noindex`). Page renders still never read `headers()`. | ADR 0006 forbids request APIs in tenant renders; a path-level signature is the only second line that works without them. Non-primary hosts already 301 to the primary. | Key rotation changes bindings (cache keys change once; harmless). |
| D3203 | `/store/resolve` and `/store/by-id/:id` responses grow additively (`description`, `showAddressField`, `soldOutBehavior`, `logoPath`, `direction`); `logo` stays as an alias for one release. Cached Valkey entries of the old shape are rejected by the shape check and re-read. | P3.S1 runs in parallel on tenancy; additive keeps both lanes compatible. | Removing the alias later. |
| D3204 | New outbox topic `store.changed` `{storeId, businessId, change: settings|status|domain}`, emitted in the store-settings transaction. | Store rename/language changes must revalidate the storefront (P1.S1 D17 left this to P3.S2). | One more topic in the shared contract. |
| D3205 | Lists, the collection filter and search read a per-store projection `storefront_product` (owned by `plugins/storefront-api`, fed by `product.changed` and `store.changed`, backfilled on boot for empty stores). `listed` folds visibility and sold-out-hide, so no `id.notIn` list is built. A `store.changed` that may change sold-out behaviour is one `UPDATE` of `listed` (columns `visible`, `sold_out`, `listed`), never a per-product rebuild. Closes the storefront part of #251; the admin-only items and `listVisible`'s `id.notIn` move to a new `after-P3` issue. | ADR 0014 names the projection; it removes the N+1 (≈ 400 queries per page) and the unbounded bind list. | Projection drift if an event is missed: a store rebuild fixes it. |
| D3206 | The product page reads `CatalogReadService.findBySlug(ctx, slug, 'productPage')`; collection membership comes from a new reviewed export `CollectionsReadService.visibleMemberIds` joined with the projection, so paging and price sort span the whole collection (#266). | Visibility stays in catalog/collections (ADR 0017, D2316). | — |
| D3207 | Theme v0: one `DEFAULT_THEME` (Arabic-first, section order of `second-pass.md` "Builder page templates") and a `COMPACT_THEME`; `STOREFRONT_THEME=default|compact` selects one for the swap criterion. Per-store theme storage is P8.S1. Reviews and FAQ sections are P8. | The AC needs a swap with no code change; storage belongs to the builder. | An env switch to remove when P8 stores themes per store. |
| D3208 | The spike E fixture (never committed) is re-created under `plugins/storefront-api/tests/fixtures/` with spike E's shape (300 names, 3 stores, 60 tagged queries) and gates recall@5 ≥ 0.85 in CI. | ADR 0014 acceptance must be re-provable in the repo. | A different fixture may score differently from the spike. |
| D3209 | Images: the API returns Vendure asset preview paths; a custom `next/image` loader maps widths to the asset server's presets (tiny 50, thumb 150, small 300, medium 500, large 800). The WebP preset job of ADR 0006 §8 stays for later (P3.S5/P8). | No derivative job exists yet; presets avoid runtime resizing. | Loader table change when derivatives land. |
| D3210 | CDN purge goes through a `CdnPurgePort`; the only adapter now is a logging no-op. The coalescer (≤ 1 purge per store per 30 s, ≤ 100 hostnames per request) is unit-tested with a fake client. The Cloudflare adapter needs the user's token (P3.S5 checklist). | Never handle tokens; ADR 0012 limits. | One adapter to add. |
| D3211 | The api's revalidate worker calls `{STOREFRONT_INTERNAL_URL}/api/internal/revalidate`, signed with `cod-internal-v1` (an `app/_internal` folder would be private and never route; the proxy matcher skips `api/`). HMAC is the gate; the edge blocks `/api/internal/*` (P3.S5 rule). | ADR 0006 gotcha: the matcher must exclude `/api/`. | One edge rule to keep. |
| D3212 | Storefront catalogues are JSON in `packages/shared/src/storefront/i18n/{ar,fr,en}.json` with a small ICU-lite formatter (`Intl.PluralRules`), checked by `pnpm i18n:check`; no `next-intl`. | ADR 0005 allows "next-intl or equivalent"; the storefront needs only lookups and plurals, and a dependency adds bundle weight. | Swap to a library if message formats grow. |
| D3213 | Public `/store/*` reads are rate-limited per buyer: the rate-limit client-ip resolver prefers the HMAC-covered `internalAuth.clientIp`; signed calls without a client ip (server renders) are keyed by kid under a high `storefront-render` limit. The storefront sends `CF-Connecting-IP` as client ip only when `STOREFRONT_TRUST_EDGE_IP=true`. | Otherwise every buyer shares the storefront's IP, or anyone forges rate-limit keys on a direct origin hit. | — |
| D3214 | Storefront in-process host LRU: 10 000 entries, 60 s positive, 15 s negative (#180); hosts outside `<label>.<PLATFORM_DOMAIN>` get 404 with no api call while custom domains are stubbed (P8.S9). Search results are not stored in the shared cache. Cache safeguards (#120): 512 KB entry cap, `{APP_ENV}:cache:writes-off` switch set by a 30 s memory guard at 60 % of `maxmemory`, 250 ms command timeout treated as a miss (#121), tag index as a sorted set scored by expiry and pruned on write and revalidate (#183). | ADR 0006 §4 values; noeviction Valkey shared with BullMQ. | Tuning constants. |
| D3215 | The storefront stays on port 3001 (`demo.localhost:3001`); the brief's `:3000` is the api port. | `.env.example` and scripts already use 3001. | — |
