# P3 decisions

Decisions taken while building phase P3. Each row gives the decision, why, and the cost if it proves wrong.

## P3.S1

| # | Decision | Why | Cost if wrong |
|---|---|---|---|
| D3100 | Commune seed source: dzCode.io **leblad** `@dzcode-io/leblad@1.0.3` data v1.1 (MIT, ONS codes and Arabic names), turned into `plugins/geo/infrastructure/seed/geo-seed.json` by the committed `scripts/geo/build-geo-seed.mjs`. Source, retrieval date and licence are in `plugins/geo/DATA-SOURCE.md`. | It is the only openly licensed commune list with ONS codes that we found; the brief asks for the public ONS list. | One regeneration from another source. |
| D3101 | ~~58 wilayas~~ **Superseded by D3123** (69 wilayas). The ten wilayas created in 2019 (49–58) still get their communes from explicit ONS code lists in the script. | — | — |
| D3102 | The six El Bayadh communes missing from the source (3207, 3208, 3213, 3218, 3220, 3221) are patched in the script with their ONS names; total 1,541 communes, the official count. The script fails on any other count. | The source's El Bayadh dairas are shifted. | A wrong Arabic name on six communes: one patch line each. |
| D3103 | Province and town tables are **global reference data** (`geo_province`, `geo_town`), not `TenantEntity`: no `businessId`, read by everyone, written only by the seed. | Brief step 2; every store reads the same map. | — |
| D3104 | A commune of a 2019 wilaya keeps its historical ONS code (Timimoun stays `109` with `provinceCode: '49'`; Bou Saada stays `2807` with `provinceCode: '68'`); `codeOns` stays the unique commune key. | ONS did not renumber (law 26-06 keeps 1,541 communes); `codeOns` must stay unique and stable for orders. | Carriers that renumber map codes in their adapter (P5). |
| D3105 | Default availability: `isHomeDelivery = true` everywhere; `isStopdesk = true` on wilaya seats (`xx01` in the 48-wilaya numbering), daira seats and at least one commune per province (495 communes). Placeholder until carriers sync real desks (P5.S4–S7). | The source has no desk data; a province with no desk would make stop-desk unusable there. | Wrong desk flags until P5: buyers may pick a desk that the carrier lacks. |
| D3106 | Per-store narrowing of the commune flags is served on a **signed** path, `GET /store/provinces/code/:code?storeId=` (under the D112 internal prefix, for the storefront server), not on the public `/provinces/code/:code?storeId` of the brief (**deviation**). The public `/provinces*` carries reference data only and ignores `storeId`. | A narrowed answer would reveal that an id is an active store and which wilayas it serves, which D112 closed for store-by-id lookups. | Mobile apps get per-store availability through the signed storefront or a later authenticated route. |
| D3107 | A fee-group rate row keeps `base_*` (platform default or carrier sync) and `override_*` (merchant edit); effective price = override ?? base. Saving a value equal to base clears the override. Sync writes only `base_*`. | "Carrier price sync keeps your overrides" (inventory) with one row per wilaya. | One migration to a separate overrides table. |
| D3108 | Deleting the store's default fee group or its platform-default group is refused (`delivery-pricing.group-in-use`); the merchant first picks another default. | A store without a fee table would quote every delivery unresolved. | One refusal to relax. |
| D3109 | Until P5.S1 a fee group's `carrierId` must be null; a non-null id is refused as not found. | No carrier entity exists to check ownership against (#153). | P5.S1 registers the carrier check. |
| D3110 | "Platform default prices" are our own placeholders in `plugins/delivery-pricing/domain/default-prices.ts`, by zone: Algiers 400 home / 250 desk; north 600/400; highlands 750/450; south 900/550; far south 1,200/800 DZD. Group defaults: charge overweight off, allowance 5 kg, rate 50 DZD per started kg. **For the user to see.** | The brief asks for our own values; carriers replace them in P5. | Wrong placeholder prices until the merchant edits them. |
| D3111 | Tenancy gains these reviewed additions: `STORE_REFERENCE_CHECK_REGISTRAR` (one `StoreReferenceCheck` per kind, `deliveryFeeGroup` or `carrier`); `StoreDeliveryDefaults` (sets a store's default fee group inside the creating transaction or the migrate converge, hook-only); `defaultDeliveryFeeGroupId` on `StoreSettings`; and a provisioning-entry directory of active stores for the converge. `updateStore` refuses a changed non-null reference id when no check is registered for its kind or the check says no. The refusal uses the pinned code `tenancy.store-reference-not-found`, byte-identical for a foreign, unknown, other-store or carrier id. The check is scoped to the store being updated, not the session's active store, and locks the group `FOR SHARE`. A fee group must belong to the same business **and** the same store. | Fixes #230/#153 without tenancy importing delivery-pricing (arch rules). | More tenancy surface to maintain; P5.S1 must register the carrier check. |
| D3112 | Existing stores get their default table from `DeliveryDefaultsConvergeService.convergeAll()` on `migrate` (like `convergeRoles`). It also repairs a default id that fails the reference check, a dangling id from before #230. A per-store failure is logged and fails `migrate`. New stores get theirs from the `storeCreated` lifecycle hook. | Same converge path as P1 roles; no manual backfill step. | A slow `migrate` with many stores (one transaction each). |
| D3113 | Speeds: only `standard` until carriers expose express (P5); `speed: 'standard'`, `offeredSpeeds: ['standard']` when resolved, `[]` and `null` when not. | The quote shape needs the fields now. | Adding speeds is additive. |
| D3114 | #207: this session adds the Default delivery fee group field; the default carrier field stays with P5.S1 (D2120). #207 stays open with a comment unless only the carrier part remains and is moved to P5.S1's brief. | Carriers do not exist yet. | — |
| D3115 | Province codes stay the existing `WilayaCode` strings `'01'`–`'58'`; `/provinces/code/:code` accepts 1–58 with or without the leading zero and answers the two-digit code. `WILAYAS` in `@cod/shared` gets all 58 names (stub owned by P3.S1). | One code type across offers, geo and delivery pricing. | — |
| D3116 | The geo seed converges on `migrate` (`GeoSeedService.converge()`, upsert, never deletes) and on demand with `pnpm seed:geo`; the migration only creates tables. | Repo precedent: flags seed on `migrate`, migrations hold no data. | — |
| D3117 | Public `/provinces` and `/provinces/code/:code` are unauthenticated, rate-limited (`provinces-ip`, named `PROVINCES_IP_CAPACITY`) and cached (`public, max-age=300, stale-while-revalidate=86400`), outside the signed prefixes. The storefront server uses the signed `/store/provinces*` (not IP-limited), so its single egress IP is not throttled. | Reference data, the same for every buyer. | Moving it behind signing is one prefix line. |
| D3118 | New reviewed arch entries: `@cod/plugin-geo` and `@cod/plugin-delivery-pricing` entries may be imported from other plugins' `infrastructure/` and `*.plugin.ts` only (like D2104). | Delivery pricing registers on geo's and offers' seams; P3.S3/P4.S3 consume `ShippingQuoteService`. | Narrowing the entries later. |
| D3119 | Catalog gains a reviewed batched product-weight reader on its public entry, scoped to the store's channel, for the shipping quote. A null weight counts as 0 g. | `CatalogProductFacts` has no weight; only packs send `weightGrams`. | One more catalog export. |
| D3120 | A rate row has `deliveryEnabled` and `deskEnabled`. Home is offered when delivery is on, desk when delivery **and** desk are on, matching the captured "Deliver to every wilaya" / "Stop desk in every delivered wilaya" toggles. Base prices are NOT NULL. | Matches the reference form; a null base had no meaning. | A third flag (home-only off) needs a column. |
| D3121 | Overweight is computed in integers, `ceil(max(0, grams − allowanceKg×1000) / 1000) × rate`. A delivery total above `MONEY_MAX_DZD` answers unresolved instead of overflowing. | Avoids float drift and integer-column overflow on absurd carts. | — |
| D3122 | Task 1 shared contracts follow the repo's naming, not the plan's: camelCase schemas (`provinceSchema`, `townSchema`, `deliveryFeeGroupInputSchema`, `deliveryFeeGroupSchema`, `shippingQuoteSchema`) as all 81 existing `@cod/shared` schemas are. `parseWilayaCodeParam` lives next to `isWilayaCode` in `wilayas/wilayas.ts`; there is no `geo/constants.ts`, since `WILAYA_COUNT` replaces `PROVINCE_COUNT`. `delivery/error-codes.ts` (`delivery-pricing.invalid-input`, `.not-found`, `.group-in-use`) is created now because the input schema needs its issue code; Task 5 extends it. A stored rate row adds `baseHomePrice`/`baseDeskPrice` to the input row so the API and the form can show an override (D3107). `Wilaya.names` stays typed nullable although every wilaya now has names, so existing callers compile unchanged. | One naming style per package; the code type and its parser stay together. | Renames are mechanical. |
| D3123 | **69 wilayas.** Law 26-06 of 4 April 2026 (JO 25/2026) amends law 84-09 to 69 wilayas and 1,541 communes. Decree 26-206 of 25 May 2026 (JO 40/2026) numbers 59 Aflou, 60 Barika, 61 El Kantara, 62 Bir El Ater, 63 El Aricha, 64 Ksar Chellala, 65 Aïn Ouessara, 66 Messaad, 67 Ksar El Boukhari, 68 Bou Saâda and 69 El Abiodh Sidi Cheikh. The seed moves the 108 communes of articles 52 bis 10–20 to them, keeping their ONS codes. Source chain: the official JO PDFs from joradp.dz (French 25 and 40, Arabic 40 for the Arabic names); the article lists transcribed by github.com/islam-re/Algeria-wilayas (MIT, bfb29814), each name checked verbatim against the official text; each name matched to a unique ONS code of its former wilaya (`scripts/geo/match-law-26-06.mjs`, every non-exact match reviewed). The build fails unless each of the 21 rewritten wilayas has its article's count. `WILAYA_CODES`/`WILAYA_COUNT` in `@cod/shared` become `'01'`–`'69'`/69, and code derives counts from them, never from a literal. me-yasserzaouag/algeria-wilayas-communes (MIT) was not used: its `wilaya_code` still puts 2019 communes in their old wilaya. | The legal division since April 2026, flagged by the user; carriers will follow it. | Carriers still on 58 need a code map in their adapters (P5). |
