# P3.S2 Multi-tenant storefront skeleton — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (run through Workflows, ultracode; P3 child rules "lighter workflows": one implementer + one reviewer/verifier per task, full adversarial review on tasks marked **RISKY**). Steps use checkbox (`- [ ]`) syntax.

**Goal:** One Next.js app serves every store by host with its own name, logo, language/RTL, products, collections and search, from a pluggable theme JSON, cached in the shared Valkey and revalidated from the outbox, never leaking one store's data under another host.

**Architecture:** `proxy.ts` resolves host → store (in-process LRU with negative entries → `/store/resolve`) and rewrites to `/_t/[storeId]/[binding]/[locale]/…`; page renders take the tenant only from route params (`'use cache'` + tags). A new `plugins/storefront-api` serves HMAC-guarded public REST `/store/*` built on a tenancy-owned *storefront store context* (`req.internalAuth.storeId` → store channel ctx) and a per-store `storefront_product` projection (listing + ADR 0014 Phase 1 search); product pages read `CatalogReadService.findBySlug`, collections read `CollectionsReadService`. Outbox events → `storefront-revalidate` job → storefront `POST /_internal/revalidate` + a coalesced Cloudflare purge (mock client).

**Tech Stack:** Next 16.4.5 (cacheComponents, proxy.ts), React 19.3, redis 6.3.1, Vendure 3.8.1 plugins (NestJS, TypeORM), Postgres 17 (`pg_trgm`, `unaccent`, `btree_gin`), zod, vitest 5, playwright-core.

## Global Constraints

- CLAUDE.md rules apply (plugin layout from `plugins/_template`, dependency direction, ≤ ~40-line functions / ≤ ~300-line files, no `any`, no magic values, no silent catch, `TenantRepository`/`tenantQuery` only, tests named by behaviour AAA).
- **No AI attribution** in commits, PR title or body (no `Co-Authored-By`, no "Generated with"). No `--no-verify`.
- One Conventional Commit per task (scope = plugin/app name); each commit builds and passes its own tests.
- Local checks only: lint, typecheck, unit tests of touched packages + `pnpm test:arch`. Integration/e2e/browser run in CI. Prelude: `export PATH="$HOME/.mise/installs/node/24.22.1/bin:$PATH"`; use `command grep/sed/cat/ls`.
- Never mint secrets (memory rule): new env keys get `.env.example` placeholders and fail-fast validation; evidence uses the existing synthetic `${VAR:-…}` pattern of `scripts/evidence/P0.S2b-5.sh`.
- Storefront holds no business rules (ADR 0017): visibility, sold-out, prices, search ranking live in plugins. The storefront app imports no plugin entry.
- Page renders under `app/%5Ft/**` never call `cookies()`, `headers()`, `draftMode()` or read `searchParams` on product/home routes (listing/search keep only `page`, `sort`, `q`).
- Own branding only; no reference-product name anywhere (ADR 0007). Logical CSS only (RTL).
- Storefront port stays **3001** (`demo.localhost:3001`); the brief's `:3000` is a typo (D3215).
- Every new entity and endpoint gets a two-business isolation test; P3 rows go to `apps/server/tests/e2e/p3-isolation.e2e.test.ts` + `apps/server/tests/isolation/cases/storefront-*.ts`.

## Review Focus

1. **Host B's data under host A** through any path: `/_t/…` with encodings (`%5f`, `%255f`, mixed case, `//_t`), `/api/store/*` with a client `storeId`, a cache key without the store, an LRU entry keyed by an un-normalised host → each returns 404/its own store (tests in Tasks 8, 9, 10, 12).
2. **Cache poisoning across stores/deploys**: an entry written for store A served for B, an entry > 512 KB, writes while `writes-off` is set, a stalled Valkey → miss, never hang or cross-serve (Task 7).
3. **Hidden/draft/sold-out(hide) products and option values** reachable through list, search, collection filter, slug, or the projection after a status change → 404/absent (Tasks 3, 5, 6).
4. **Malformed public input**: non-numeric/overflowing ids, `take` > max, empty/2-char/huge/RTL-mark `q`, unknown collection slug → 404 or clamped, never 500 or raw error text (Tasks 6, 9).
5. **Store language/settings change** not reaching the storefront (stale LRU, stale tags) → visible within LRU TTL + one revalidate (Tasks 4, 8, 11).
