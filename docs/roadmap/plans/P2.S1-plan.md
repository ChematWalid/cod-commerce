> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. **Goal:** Merchants manage their store catalog in the dashboard: products on Vendure `Product`/`ProductVariant` with our fields, a variant matrix (options × values, SKU `<sku>-n`, custom price, hidden), status Active / Hidden / Draft, brands, tags, highlights (max 6), SEO, product settings, a per-business media library with image upload, sold-out behaviour with stop/resume orders, a product list with tabs, filters and search, and a product editor. The 14 P2.S1 audit issues are fixed test-first and 2 are moved.

**Architecture:** New feature plugin `plugins/catalog` copied from `plugins/_template` (layout) and `plugins/team` (REST + GraphQL over one `*Actions` class, zod in `@cod/shared`, translated errors, outbox, endpoint registries). Catalog calls Vendure **services** (`ProductService`, `ProductVariantService`, `ProductOptionGroupService`, `ProductOptionService`, `AssetService`, `ChannelService`) inside the tenant's store channel behind its own `catalog*` GraphQL operations and `/catalog/*` REST routes guarded by `requirePermission('catalog.products.*')`. Merchants get **no** stock Vendure grant. Our own data (brands, tags, highlights, product settings, media index) are `TenantEntity` tables behind `TenantRepository`. Dashboard pages fill the shell leaf `products.all` and two store-scoped routes through a new shell-api export.

**Tech Stack:** Vendure 3.8.1, NestJS 12, TypeORM 0.3.31 (Postgres 17, Valkey 8), zod 4.6.7 in `@cod/shared`, React 19 + `@vendure/dashboard` 3.8.1 + Lingui `.po`, Tailwind 4.3.5, Vitest 5.1.0 (unit, integration, e2e), `playwright-core` 1.65.0 (browser tests and evidence).

**Spec:** `docs/roadmap/P2-catalog-offers.md` section P2.S1 (brief); `docs/research/data-model.md` "Product"; `docs/research/second-pass.md` "Products"; `docs/research/dashboard-captures.md` "Products `/stores/:storeId/products`" and "Store settings → Profile"; `docs/research/api-surface.md` "Catalog & store"; `docs/feature-inventory.md` rows 19, 115-118, 125, 131; `docs/audits/P1-audit.md`; ADR 0002, 0003, 0004, 0005, 0007, 0010, 0014, 0017, 0018; `docs/roadmap/P1-decisions.md` (D1, D2, D10, D59, D83, D84, D92, D206, D209, D218, D500, D801).

## Review Focus

1. **Arabic titles and slugs** (Task 11): a product titled `حذاء رياضي أحمر` gets slug `حذاء-رياضي-أحمر` (Vendure `normalizeString`, stored NFD); `catalogSlugAvailability` with the NFC form of the same slug reports it taken; the same slug in a store of business B is available. Test: `slug-availability.int.test.ts` "reports an Arabic slug taken whatever its Unicode normal form".
2. **Hostile uploads** (Task 13): a PNG header with a `.jpg` name is accepted as PNG; an SVG, an HTML file renamed `.png`, a 5 242 881-byte JPEG and a zero-byte file are refused with `catalog.media-type` / `catalog.media-too-large`, and nothing is stored (no asset row, no `catalog_media` row). Tests in `media-upload.int.test.ts`.
3. **Options edited after variants were edited** (Task 9, Task 11): removing value `M` from Size keeps the prices, SKUs and hidden flags of `Red / S` and `Blue / S`; re-adding `M` creates new variants with the next free SKUs (never a SKU still held by a live variant). Test: `variant-matrix.test.ts` "re-adding a removed value takes the next free sku".
4. **Rich-text description with script** (Task 11): `<p onclick="x">a</p><script>b</script><img src=x onerror=y>` is saved as `<p>a</p>`; links keep only `http(s)`/`mailto` `href` and get `rel="noopener noreferrer"`. Test: `description-sanitizer.test.ts`.
5. **Display language ≠ store language** (Task 11, Task 16): a dashboard in English editing a product of an Arabic store writes and reads the `ar` translation; the list never shows an empty name. Test: `product-crud.int.test.ts` "writes the product name in the store language whatever the display language".
