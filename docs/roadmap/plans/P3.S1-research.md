# P3.S1 research: how P1/P2 solved the same things

Pattern map produced by the research agent on 2026-11-22 (read-only survey of the repo at `origin/phase/P3` 2db0bdb2). Paths are relative to the repo root.


- **Store id typed as `'7'` in an existing test:** `plugins/tenancy/tests/integration/store.api.int.test.ts:92-125` sets `defaultCarrierId: '7'` and some made-up snowflakes. Once you add the ownership checks, those cases will fail unless the ids exist.
- **Geo work already started (untracked):** `plugins/geo/DATA-SOURCE.md`, `plugins/geo/infrastructure/seed/geo-seed.json` (58 provinces with communes) and `scripts/geo/build-geo-seed.mjs` exist but are not committed.
- **Offers already has a slot for your quote service:** `plugins/offers` exports `SHIPPING_QUOTE_REGISTRAR` and a `ShippingQuoteSource` interface waiting for P3.S1 to register. Until then every delivery comes back unresolved with fee 0.

## 1. Plugin layout

**Template (`plugins/_template`)**
- Files: `index.ts`, `template.plugin.ts`, `package.json`, `tsconfig.json`, `tsconfig.build.json`, `vitest.config.ts`, `vitest.integration.config.ts`, `README.md`.
- Folders: `api/` (dto, error-mapping, permissions, schema, resolver), `application/` (services, `tokens.ts`), `domain/` (constants, errors, ports), `infrastructure/`, `dashboard/` (index.tsx, routes, i18n/ar.po and en.po, tsconfig.json), `tests/` (setup-env.ts, fakes, integration).
- `package.json`: name `@cod/plugin-<name>`; exports `{ ".": { "@cod/source": "./index.ts", "default": "./dist/index.js" } }`. Scripts: `typecheck` is `tsc --noEmit -p tsconfig.json && cod-typecheck-own dashboard/tsconfig.json`, `test` is `vitest run --configLoader runner`, `test:integration` adds `-c vitest.integration.config.ts`.
- `tsconfig.json` extends `@cod/config/tsconfig.vendure.json` and excludes `dashboard`.
- The vitest configs spread `vendurePreset` from `@cod/config/vitest/vendure`. The integration one includes `tests/**/*.int.test.ts` and sets `expect.requireAssertions: true`.
- Plugin class: `@VendurePlugin({ imports: [PluginCommonModule, TenancyPlugin], entities, providers, adminApiExtensions: { schema, resolvers }, dashboard: './dashboard/index.tsx', compatibility: '^3.8.0' })`. Use cases are plain classes built with `useFactory`.
- Step-by-step guide (copy, register, migrate, PR checklist): `plugins/_template/README.md` §"How to add a feature" (lines 49-105).

**Reference P2 plugin: `plugins/catalog-packs`**
- Module: `catalog-packs.plugin.ts`.

- Entity: `infrastructure/pack.entity.ts`.

- Services: `application/*.service.ts`, ports in `domain/ports/*.port.ts`, tokens in `application/tokens.ts`.
- GraphQL schema: `api/schema.ts`, built with `gql`. Type names carry a plugin prefix (`CatalogPack…`), and money is `Int` "in whole DZD".

- Shared contract for the plugin: `packages/shared/src/catalog-packs/{constants,error-codes,schemas,index}.ts`.

## 2. Tenancy

- **Base entity:** `plugins/tenancy/infrastructure/tenant.entity.ts`. `TenantEntity` adds `@Index() businessId: bigint` (required) and `storeId: bigint | null`. Entities extend it, as `PackEntity` does.
- **Repository:** `plugins/tenancy/infrastructure/tenant-repository.ts`.
  - `TenantRepository<T>` has `findOne`, `find`, `insert`, `update`, `delete`, `count`, `query(scope, alias)` and `inTransaction`.
  - Every call forces `businessId: scope.businessId` and throws `TenantScopeMissingError` when it is missing.
  - `TenantRepositoryFactory.for(Entity)` builds one; `tenantQuery(scope, repo, alias)` gives a query builder already limited to the business.
  - All three are exported from `plugins/tenancy/index.ts`.
- **Store filter:** the plugin adds it itself, e.g. `const inStore = (s) => ({ storeId: s.storeId })` in `typeorm-pack.repository.ts`.
- **Joining the request's transaction:** `plugins/catalog-packs/infrastructure/request-scope.ts` does `new RequestTenantScope(toRequestContext(ctx), scope.businessId)`.
- **Tenant context in a resolver:** `plugins/catalog-packs/api/store-scope-of.ts`.
  ```ts
  const { businessId, activeStoreId } = tenantOf(ctx);
  return { businessId, storeId: activeStoreId };
  ```
  `tenantOf` (`plugins/tenancy/api/tenant-of.ts`) throws unless `@TenantScoped()` ran; `requirePermission` applies that for you.
- **Not-found codes for foreign ids:** each plugin has its own constant in `packages/shared/src/<area>/error-codes.ts`. Examples: `packs.not-found`, `packs.component-not-found`, `catalog.product-not-found`, `collections.not-found`, `offers.offer-not-found`, `tenancy.store-not-found` (`plugins/tenancy/domain/errors.ts`, `StoreNotFoundError`). A foreign id gets the same answer as a missing one.
- **Ownership checks of referenced ids:**
  - `plugins/offers/application/target-check.ts`, `assertTargetsInStore(catalog, ctx, scope, targets)`. It calls a port's `existing(ctx, scope, wanted)` and throws `UnknownOfferTargetsError` unless every id is found.
  - `plugins/tenancy/application/asset-rules.ts`, `assertAssetInChannels(...)`, throws `AssetNotAvailableError`. `UpdateStoreService.assertLogoAllowed` already uses it in `update-store.service.ts`.
  - `plugins/tenancy/application/store-access.ts`, `requireStore` / `requireActiveStore`, throws `StoreNotFoundError` when the store is foreign or out of reach.
  - Isolation case: `apps/server/tests/isolation/cases/packs.ts`, `SAVE_WITH_FOREIGN_COMPONENTS`, expects `COMPONENT_NOT_FOUND`.

## 3. RBAC

- **Catalogue:** `packages/shared/src/permissions/catalog/{orders,products,operations,storefront,define,index}.ts`, with areas in `packages/shared/src/permissions/areas.ts`.
- **Delivery keys already exist** in `catalog/operations.ts`, `DELIVERY_PERMISSIONS`: `delivery.pricing.{create,view,edit,delete}` and `delivery.carriers.{connect,view,edit,delete}`. They are declared with `delivery.full/view/sensitive(key, en, ar)`.
- **Naming:** `area.resource.action`. Vendure names come from `vendurePermissionName` (`packages/shared/src/permissions/vendure-name.ts`): `delivery.pricing.view` becomes `CodDeliveryPricingView`.
- **Registration:** `plugins/rbac/api/permission-definitions.ts` maps the whole catalogue to `PermissionDefinition`s. Do not define your own (template README).
- **Guard:** `requirePermission(key)` from `@cod/plugin-rbac/guard` (`plugins/rbac/api/require-permission.decorator.ts`). It applies `Allow(vendureName)` plus `TenantScoped()`.
- **Arch gate:** `packages/config/tests/handler-permissions.test.ts` fails on any handler without a guard. Public handlers must use `@Allow(Permission.Public)`.
- **`updateStore` is different:** it uses `@Allow(tenantStorePermission.Update) @TenantScoped()` (`plugins/tenancy/api/store.resolver.ts:131-143`, permissions in `plugins/tenancy/api/permissions.ts`).

## 4. Migrations and seeds

- **Seed scripts:** `apps/server/package.json` has only `seed:demo` (`src/main-seed-demo.ts`, using `seed-demo-{businesses,members,products}.ts`).

## 5. Public REST endpoints

- **Existing public controllers:**
  - `plugins/tenancy/api/store-resolve.controller.ts`: `@Controller('store')`, `GET resolve?host=`, `GET by-id/:storeId`, both `@Allow(Permission.Public)`, `NotFoundException` when there is no match.
  - `plugins/tenancy/api/subdomain.controller.ts`: `@Controller('stores')`, `@Allow(Permission.Public) @RateLimit('subdomain-ip')`.
  - Also: `plugins/auth/api/*.controller.ts`, `plugins/team/api/invitations.controller.ts`, `plugins/platform-webhooks/api/webhook.controller.ts`.
- **Registration:** the `controllers: [...]` array on `@VendurePlugin`, as `CATALOG_PACKS_REST_CONTROLLERS` does.
- **Signed-request guard:** `plugins/platform-webhooks/domain/internal-prefixes.ts` makes the Shop API path, `/store` and `/_internal` reachable only by signed internal callers (D112). It is mounted in `platform-webhooks.plugin.ts:172`.
  - A new `/provinces` route is **outside** that guard and fully public.
  - Express matching is per segment, so `/stores/*` is not covered either.
  - The storefront signs its calls with `internalFetch` (`apps/storefront/src/lib/internal-api.ts`) and resolves its store in `apps/storefront/src/tenancy/api-store-resolver.ts` (`GET /store/resolve`, `/store/by-id/:id`).

- **Cache headers:** only `Cache-Control: no-store` in `plugins/team/api/no-store.ts`. No public caching or ETag pattern found. No bot protection found.

## 6. Reacting to store creation

- **Mechanism:** the in-transaction hook registry, not the event bus or outbox.
  - Interface: `plugins/tenancy/domain/ports/tenant-lifecycle.port.ts`, `TenantLifecycleHook { businessProvisioned(ctx, e); storeCreated(ctx, e: StoreCreatedEvent { businessId, storeId, channelId }) }`.
  - Registry: `plugins/tenancy/application/tenant-lifecycle.registry.ts`. Hooks run in order inside the creating transaction; a throw rolls the creation back.
- **Firing:** `plugins/tenancy/application/create-store.service.ts:139` `openStore` calls `this.ports.lifecycle.storeCreated(...)` right after `saveStore`. The first store of a new business also goes through `openStore` (`provision-business.service.ts` `createIn`).
- **Examples:**
  - `plugins/team/infrastructure/team-lifecycle.hook.ts`:
    ```ts

      constructor(@Inject(TENANT_LIFECYCLE_REGISTRAR) private readonly registrar: TenantLifecycleRegistrar, ...) {}

    ```

- **No P2 plugin seeds per-store defaults today.** Only rbac and team register hooks.

A check would need a seam inside tenancy (a port plus registrar, like `TENANT_LIFECYCLE_REGISTRAR`), filled by delivery-pricing. Tenancy has no such seam today; its tokens are in `plugins/tenancy/application/tokens.ts`.
- **Error mapping:**
