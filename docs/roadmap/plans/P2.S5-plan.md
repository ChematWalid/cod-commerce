**Goal:** Add the BXGY and add-on kinds to the offer engine and ship the full offers admin: GraphQL + REST endpoints (list, CRUD, lifecycle, duplicate, codes, generate, stats, app types, preview), the dashboard list, 7-card create dialog, per-kind editors with shared sections, live summary and Arabic order-form preview, and the product editor's Offers block.

**Architecture:** Everything stays in `plugins/offers` (D2400 layout). The admin use cases extend `OfferAdminService` and add small services (`OfferStatsService`, `OfferPreviewService`, `OrderAddonService`); `api/` wraps them for GraphQL and REST exactly as `plugins/catalog/api/` does (actions class shared by both surfaces, one error mapping, `@requirePermission`). `dashboard/` registers shell pages like `plugins/catalog/dashboard/index.tsx`; it never imports the engine (`dashboard-no-plugin-core`): the summary numbers, warnings and Arabic preview come from the `previewOffer` endpoint (ADR 0017).

**Tech Stack:** Vendure 3.8.1, NestJS 12.4.0, TypeORM 0.3.31 (Postgres 17), zod 4.6.7, Vitest 5.1.0, React + `@vendure/dashboard` + TanStack Router/Query (versions pinned as in `plugins/catalog/package.json`), Lingui `.po` catalogues, Playwright (`playwright-core` from `apps/server`).

## Review Focus

1. **Gift units on a mixed cart** (Task 4): buy-2-get-1 with two variants at 4,900 and 3,900 (2 + 1 units) gifts the 3,900 unit (cheapest first, D2504), the paid line keeps `totalPrice = unitPrice × quantity`, and a quantity tier on the same product still counts 3 pieces. Test: `bxgy.test.ts` "gifts the cheapest matched unit on a mixed cart"; `pipeline-gift.test.ts` "counts gift units in the tier pieces and keeps every line's total exact".
2. **Add-on tampering** (Task 5): a token signed for a cart with add-on A fails `cart_mismatch` when verified with add-on B, a different quantity, or no add-on; an add-on for an offer of store A2 or business B is rejected `not_offered` and never priced. Tests: `cart-hash.test.ts` "changes h when an add-on changes", `pricing-service-addons.test.ts` "rejects an add-on of another store's offer as not_offered", `offers-isolation.int.test.ts` "does not price an add-on offer of another business".
3. **Same code string in two businesses** (Tasks 7, 10): `SAME10` exists in business A and B; A's quote applies A's offer only, A's code list shows only A's row, A can add `SAME10` to a second offer only after removing its own (per-store unique), and A removing `SAME10` leaves B's row untouched. Tests: `offers-sweep.ts` cells, `offer-codes.int.test.ts` "keeps the same code in two businesses apart".
4. **Publish of an incomplete draft** (Task 7): a quantity draft without targets, with a blank title, or with `endsAt` in the past fails `offers.publish-invalid` listing every problem (`['title','targets','dates']`), stays `draft` and keeps `publishedAt` null; an order-discount draft with no target publishes. Test: `offer-publish.test.ts` "lists every publish problem at once" and "publishes a kind that needs no target".
5. **Preview with odd inputs** (Task 8): a preview of a quantity draft in total-price mode with a tier total not divisible by its quantity returns the priced scenarios plus warning `tier_total_not_divisible`; a sample price of 0, above `MONEY_MAX_DZD`, or a draft whose config fails its schema returns `offers.invalid-config` / `pricing.invalid-request`, never a 500 and never a DB write. Test: `offer-preview.service.test.ts` cases of those names; `offers-api.int.test.ts` "previews without writing a row".
