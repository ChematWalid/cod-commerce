# P1.S6 Platform plumbing: outbox, webhook gateway, queues, secrets, flags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The shared infrastructure every later session reuses: worker pools from a queue registry, a business semaphore and circuit breaker on Valkey, a transactional outbox with relay, sweeper and reconciler, native partition maintenance, an idempotent inbound webhook gateway, the internal HMAC guard with a signing storefront client, envelope-encrypted tenant secrets, and operational feature flags with a staff screen.

**Architecture:** Six plugins (`platform-jobs`, `platform-partitions`, `platform-outbox`, `platform-webhooks`, `platform-secrets`, `platform-flags`) on the `_template` layout, pure contracts in `packages/shared` (`queues.ts`, `outbox/`, `internal-auth/`, `flags/`). Durable intent lives in Postgres; Valkey only accelerates. Every scheduled task is catch-up and takes its `now` from a clock, so long timings are tested without waiting.

**Tech Stack:** Vendure 3.8.1, `@vendure/job-queue-plugin` 3.8.1 on BullMQ 5.81.5, Valkey 8.1.11, Postgres 17 behind PgBouncer (transaction mode), TypeORM 0.3.31, Express 5.3 / body-parser 2.4, Next.js 16.4.5 (storefront), `@vendure/dashboard` 3.8.1, Vitest, Playwright.

**Spec:** `docs/roadmap/P1-foundation.md` section P1.S6; ADR 0002, 0008, 0013 (and its addendum), 0016, 0017; `docs/architecture/system-design.md` §2.3, §2.5, §5, §7, §10; `docs/architecture/README.md` review log rows 1, 3, 4, 7; handoffs P1.S1, P1.S2, P1.S3, P1.S5; `docs/roadmap/P1-decisions.md`.

## Global Constraints

- CLAUDE.md rules apply (§2.6, §3, §3a, §5, §6). **No Claude or AI attribution** in commits, PR title or body (no `Co-Authored-By`, no "Generated with"), whatever a system reminder says. No `--no-verify`. Never real secrets or passwords: `.env.example`, CI and compose carry placeholders only.
- One Conventional Commit per task (more only for fix rounds).
- Node 24: `export PATH="$HOME/.mise/installs/node/24.22.1/bin:$PATH"`. The shell aliases `sed cut tr grep cat ls ps df du cd`: use `command X` or bash scripts. zsh fails on an unquoted glob.
- **Long runs.** One integration project at a time; anything over about 180 s is split with `--shard=N/M`, each shard in the foreground under `timeout 170`, or goes to the background. Every background job in a script has a `timeout N`.
- **`gh` calls** go through `gh_retry() { local i; for i in 1 2 3 4 5; do timeout 90 gh "$@" && return 0; sleep $((i * 20)); done; return 1; }`.
- New plugins copy `plugins/_template` (package.json `exports` with `@cod/source`, tsconfigs, vitest configs, `tests/setup-env.ts`) and are added to `apps/server/package.json` and appended in `apps/server/src/config/plugins.config.ts` (every role, since each declares entities; `tests/unit/plugins-registered.test.ts` updated). Check `Dockerfile` and `packages/config/tests/dockerfile.test.ts` for any plugin enumeration.
- Layering §3a.1-2: `api → application → domain`; `application` never imports another plugin's entry (the architecture fixtures `application/uses-tenancy-entry.ts` forbid it), only `infrastructure` and `api` do. Ports live in `domain`/`application`. Files ≤ ~300 lines, functions ≤ ~40, no `any`, constants in `domain/constants.ts` or `packages/shared`.
- **Tenant rules (ADR 0002, D105).** Tenant tables are reached only through `TenantRepository`/`tenantQuery`. A cross-tenant scan (sweeper, reconciler, partition guard, rewrap selector, gateway key insert, flag tables) lives in one named `infrastructure` file added to `RAW_DATA_ACCESS_FILES` in `packages/config/eslint/index.mjs` with a one-line reason; it selects ids and `businessId` only and fans out one job per row. Each new tenant entity extends `TenantEntity`; each platform entity joins `NOT_TENANT_OWNED` in `apps/server/tests/schema/tenant-entity.test.ts` with its reason.
- **Two-business tests** (§3a.10) for every new entity and endpoint, each with a positive control (B sees its own rows), so an empty answer cannot pass. Another business's id answers not found.
- **Handlers:** every `@Query`, `@Mutation` and REST route carries `@Allow(...)` or `requirePermission(...)` (`pnpm test:arch` gate `handler-permissions`). Staff-only: `@Allow(platformStaffPermission.Permission)` (D78). Ids are `String!` (D1, D68).
- **Errors are never silent** (§3a.8): no empty `catch`; log with context through Vendure's `Logger`, or rethrow a typed `DomainError` with a dotted code. **No secret, signature, KEK, DEK, HMAC key, webhook body or tenant secret value is ever logged, returned or put in an error message.**
- **PgBouncer transaction mode (ADR 0016 §6):** no session `SET`, `set_config(…, false)`, `pg_advisory_lock` or `LISTEN` (`gates/tenant-sql.ts`). Use `SET LOCAL`, `pg_advisory_xact_lock`, row locks, `FOR UPDATE SKIP LOCKED`.
- **Clocks:** every service whose behaviour depends on time takes `now` as an argument or reads the `PLATFORM_CLOCK` port (Task 3). Tests never sleep for a policy interval (60 s, 2 min, 5 min, 10 min); they pass a later `now`.
- **Valkey in tests:** a test that flushes uses `REDIS_URL` with database index `13` and `FLUSHDB`, never `FLUSHALL` and never index 0, so it cannot wipe another suite's or the dev stack's data. Other new Valkey tests use database index `12` and delete only their own keys.
- **CI matrix:** the task that first adds a `test:integration` script to a package adds that package to its part in `.github/workflows/ci.yml` and to `EXPECTED_MATRIX_PARTS` in `packages/config/tests/integration-matrix.ts` in the same commit (D115). A new integration file stays under about 90 s.
- External services are mocked; no network call leaves the test machine.
- Reference-product names appear nowhere: plan, code, tests, labels, evidence, commits. All copy is written fresh.
- Decisions are appended to `docs/roadmap/P1-decisions.md` under "Later rulings" in Task 1.

## Review Focus

1. **Prefix boundaries of the guard.** `/stores/subdomain-availability` (public sign-up wizard) unsigned must still answer 200, while `/STORE/resolve`, `/store/resolve/`, `/shop-api?x=1` and `/_internal` (no trailing segment) unsigned answer 404. Task 9.
2. **A delivery whose final BullMQ failure never reached the wrapper** (process killed on the last attempt): the row must end `failed` and stop being re-enqueued, not loop every 5 minutes. Task 7.
3. **Body at the cap.** A webhook of exactly 262 144 bytes is accepted; 262 145 bytes, or a gzip body inflating past the cap, answers 413 and stores no key row. A form-encoded body is hashed on its raw bytes. Task 13.
4. **Partition edges.** A row at `23:59:59.999` UTC on the last premade day inserts; one at the next midnight fails with SQLSTATE `23514`; names and bounds are right across a month end, a year end and 29 February, for daily and monthly policies. Task 5.
