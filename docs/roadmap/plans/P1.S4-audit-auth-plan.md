# P1.S4 audit — auth fixes: executable plan

**Goal:** close the 9 auth audit findings assigned to P1.S4 (`docs/audits/P1-audit.md`) in one PR, test first.

**Branch:** `fix/s4-audit-auth` (from `origin/main` 52e9c93). **Issues:** #110, #111, #141, #145, #146, #147, #148, #151, #152. Runs in parallel with the P1.S4 core session; scope is `plugins/auth` and `plugins/rate-limit` only.

## Global constraints
- CLAUDE.md rules apply (§3a layering, no `any`, ≤300 lines per file, ≤40 lines per function, typed errors, no magic values).
- No AI attribution in commits, PR title or body; no `--no-verify`; never push to `main`; never force-push.
- Never handle tokens or passwords; test secrets come from `apps/server/tests/support/deployed-env.fixture.ts`; no new high-entropy literals.
- Heavy jobs run under `flock -w 3600 /tmp/cod-heavy-jobs.lock timeout 1800 …`; locally only lint, typecheck, unit tests and the `plugin-auth` / `plugin-rate-limit` integration suites.
- Decisions are pre-approved: take the recommended option and log it in `docs/roadmap/P1-decisions.md` from D600 up.

## Method
Per issue: a failing test first (shown failing), the fix, one Conventional Commit, a fresh reviewer, then an adversarial verify by three lenses (correctness, security, does-it-reproduce). Fix rounds until no verifier finds the issue open. Then a whole-branch review and a `security-review` pass.
