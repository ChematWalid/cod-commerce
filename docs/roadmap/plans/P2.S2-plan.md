**Goal:** Merchants build Pack (bundle) products with pricing, discount, variant and weight modes; bulk-edit selected products; export products to xlsx/CSV; import a spreadsheet through upload → analyze → preview → confirm with per-row reports; and create a Draft product from a link (stub scraper), with AI polish and image clean-up as no-op hooks for P9.S7b.

**Architecture:** Two new feature plugins copied from `plugins/_template`: `plugins/catalog-packs` (pure pack calculators in `domain/`, `catalog_pack` tables, pack editor block, `PackUnitPriceResolver`, order-line expansion helper) and `plugins/catalog-import` (bulk edit, export, import, link import, `ObjectStorage` port on the private Garage bucket, the `imports-exports` queue). Both write products only through a new explicit-scope write facade `CatalogProductCommands` exported by `plugins/catalog` (the one recorded catalog deviation, D2201), so catalog validation, locks and `product.changed` stay in catalog. Uploads and downloads use presigned URLs issued only after the tenant owns the job.

**Tech Stack:** Vendure 3.8.1, NestJS 12, TypeORM 0.3.31 (Postgres 17, Valkey 8), BullMQ via `@cod/plugin-platform-jobs`, zod 4.6.7 in `@cod/shared`, `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` 3.1164.0 (Garage v2.5.0), `exceljs`, `csv-parse` 7.0.2, `csv-stringify`, `node-html-parser` (exact pins), React 19 + `@vendure/dashboard` 3.8.1 + Lingui `.po`, Vitest 5.1.0, `playwright-core` 1.65.0.

## Review Focus

1. **Excel-saved CSV from an Arabic or French Windows** (Task 9): `;` delimiter, UTF-8 BOM, CRLF, Arabic header aliases (`الاسم`, `السعر`) → analyze detects delimiter and maps every column. Test `spreadsheet-reader.test.ts` "reads a semicolon CSV with BOM and Arabic headers".
2. **Formula injection round trip** (Tasks 8, 9): a product named `=HYPERLINK("x")` exports as `'=HYPERLINK("x")` in CSV and xlsx (text cell), and re-imports as the original name. Tests `cell-guard.test.ts` "prefixes cells starting with = + - @ tab or CR" and `round-trip.int.test.ts`.
3. **Duplicate and ambiguous SKUs** (Task 9): two rows with the same `variant_sku` → the second is an error "duplicate in file"; a SKU held by two variants of the store → "ambiguous"; a SKU only held in business B → a create in A, B untouched. Tests `row-plan.test.ts`, `import-isolation.int.test.ts`.
4. **Double confirm** (Task 9): two concurrent `confirm` calls on one previewed import → exactly one job runs, the other answers 409 `catalog-import.job-state`; a re-PUT of the file after preview (ETag changed) → confirm refused. Test `import-confirm.int.test.ts`.
5. **Hostile files** (Tasks 6, 9): an HTML file named `.xlsx`, a zip that is not an xlsx, a 10 MiB + 1 object, an object whose size differs from the declared one, 5 001 data rows, an xlsx cell holding a formula (cached value used, formula never evaluated), a deflate bomb, a 16 384-column row, a `<!DOCTYPE` entity, a single 10 MiB CSV line → refused before or while parsing, nothing written (D2222). Tests `zip-inspect.test.ts`, `file-sniff.test.ts`, `spreadsheet-reader.test.ts`, `import-flow.int.test.ts`.
6. **Retried confirm** (Task 9): a confirm job that fails midway and is retried by BullMQ (attempts 2) or re-enqueued by the reconcile source creates no duplicate (rows marked `applied` in the facade's transaction). Test `import-confirm.int.test.ts` "a retried confirm job creates no duplicate".
7. **SSRF** (Task 10): redirects, DNS rebinding, alternative IPv4 spellings, IPv6 transition ranges, proxy env vars, internal host names (D2214). Tests `ssrf.test.ts`, `http-link-scraper.test.ts`.
