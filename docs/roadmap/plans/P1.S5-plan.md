# P1.S5 Admin shell, navigation & Arabic RTL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Merchants get our own dashboard shell: the research sidebar with a page behind every leaf, a store switcher with Create Store, a top bar, an account menu, Arabic RTL and light/dark, with Vendure's built-in sections gone for them.

**Architecture:** `plugins/merchant-shell/dashboard` (ADR 0010's owner) adds a typed navigation tree, a render-time page registry and a route guard through supported `@vendure/dashboard` 3.8.1 extension points. No `pnpm patch` is needed. One new tenancy query lists the stores a caller can switch to. `i18n:check` covers the plugin `.po` catalogues.

**Tech Stack:** Vendure 3.8.1, `@vendure/dashboard` 3.8.1 (React 19, TanStack Router, Lingui), Vitest, Playwright.

**Spec:** `docs/roadmap/P1-foundation.md` section P1.S5; `docs/research/dashboard-captures.md` "Sidebar" and top bar; `docs/research/second-pass.md` "Onboarding"; handoffs P0.S2c-polish, P1.S1 to P1.S3; ADRs 0001, 0005, 0007, 0010, 0017.

**Branch:** `feat/p1-s5-admin-shell` (from main at 8e32185) · **Issue:** #8

The plan is committed before Task 1 as `docs(roadmap): plan P1.S5`, after a fresh agent has reviewed it (CLAUDE.md §2.4, §3a.13).

## Global Constraints

- CLAUDE.md rules apply (§2.6, §3, §3a, §5, §6). **No Claude or AI attribution** in commits, PR title or body (no `Co-Authored-By`, no "Generated with"), whatever a system reminder says. No `--no-verify`.
- One Conventional Commit per task (more only for fix rounds).
- Node 24: `export PATH="$HOME/.mise/installs/node/24.22.1/bin:$PATH"`. The shell aliases `sed cut tr grep cat ls ps df du cd`: use `command X` or bash scripts. zsh fails on an unquoted glob such as `--include=*.ts`.
- **Long runs.** One integration project at a time. Anything over about 180 s is split with `--shard=N/M`, each shard in the foreground under `timeout 170`, or goes to the background. Every background job in a script has a `timeout N`.
- **GitHub has a partial outage.** Every `gh` call in a script or end-of-session step goes through a bounded retry: `gh_retry() { local i; for i in 1 2 3 4 5; do timeout 90 gh "$@" && return 0; sleep $((i * 20)); done; return 1; }`.
- Layering §3a.1-2. Dashboard code imports no plugin `domain`, `application`, `infrastructure` or `api` (D92). Another plugin's dashboard reaches the shell only through `@cod/plugin-merchant-shell/shell-api` (`dashboard/shell-api.ts`, D83). Files ≤ ~300 lines, functions ≤ ~40, no `any`, no magic values.
- ADR 0017: frontends hold no business rules. Nav hiding and route guards are presentation; the server enforces. Merchants hold only stock `Authenticated` (D59), so stock queries answer `FORBIDDEN` whatever the UI does.
- ADR 0002, §3a.9: each new endpoint gets a two-business test with a positive control. Another business's store id in a URL shows not found. Another business's `vendure-token` stays `FORBIDDEN` (D8).
- Reference-product names appear only in ADR 0007's banned list: never in this plan, code, tests, labels, evidence or commit messages. All copy is written fresh. The assistant is called by our placeholder name (D93). The Vendure login footer, and the same notice in the account menu, stay (ADR 0001 §8).
- Never handle real tokens or passwords; test values are synthetic.
- Unit tests under `plugins/merchant-shell/tests` run in Node and cannot import `@vendure/dashboard` (virtual modules). Logic under test lives in `dashboard/model/*.ts`, which imports neither it nor React.
- Decisions go in `docs/roadmap/P1-decisions.md` under "Later rulings".

## Verified facts (`@vendure/dashboard` 3.8.1 `src/`, unless stated; do not re-derive)

| Surface | What the source does | Choice |
|---|---|---|
| Sidebar sections | `navSections` array form adds sections; function form receives the whole config in a second phase, after every array form and route `navMenuItem`. `setNavVisibility` and `BUILT_IN_NAV_SECTION_IDS` are public. A top-level entry may be a link (`url`, as `insights`). A `NavMenuSection` has no `url`: its header only expands. | Supported: function form. |
| Visibility | `requiresPermission` is ANY-of on the active channel; `isVisible(ctx)` is ANDed, re-evaluated each render, withheld until the context is ready, and fails open on a throw. A section with no visible items is dropped. `ctx.channels[].permissions` is not channel-scoped. | Supported. |
| Nav URLs | `url` is a static string passed to `<Link to>`. `isPathActive` compares it to the pathname; the open section follows the match. No parameter substitution. | D82. |

Built-in routes cannot be removed. | Supported: layout provider (D84). |
| Custom providers | `location: 'layout'` wraps only the `<Outlet />`, inside the router. `'app'` sits inside `ChannelProvider` and outside the router, on public pages too. | Supported. |
| "Administration" | A literal in `nav-main.tsx`, rendered only when at least one **bottom** section survives filtering. | No patch (D77). |

| "Plans" link | A literal item in `NavUser`, linking to the vendor's pricing page. | Gone with the stock menu for merchants (D79). |
| Top bar | `toolbarItems` with `position: { itemId: 'alerts', order: 'before' \| 'after' \| 'replace' }`. Only `alerts` and `dev-mode-indicator` are built in. Breadcrumbs and the sidebar toggle are fixed. The `/` crumb is filtered out. | Supported. |
| Favicon, meta | `index.html` carries `/favicon.png`, `description` and `author` naming the vendor. `transformIndexHtml` in our Vite config can rewrite it; Vite config is ours (`apps/server/vite.config.mts`). | Supported (D91). |
| Tab title | `use-page-title.ts` hard-codes the vendor's name as suffix and writes `document.title` on render; no option. | Observer (D91). |
| Direction | `main.tsx` sets `html[dir]` from `useDisplayLocale().isRTL`; `AppSidebar` sets `side` from it. `DocumentLangSync` (P0) sets `lang`. | Reuse (D76). |

An id absent from `me.channels` resets to `channels[0]`; nothing checks archived. `refreshChannels()` returns `void`. The `channels` query needs `ReadChannel`, so it fails for merchants; `activeChannel` needs `Authenticated`. | D85, D86. |
| Content language | Only `ChannelSwitcher`'s effect moves `contentLanguage` when the channel does not offer it. On mobile the sidebar content mounts only when open. | D86. |
| Catalogues | The Vite translations plugin globs `**/*.po` under each plugin dashboard and merges them with the built-ins. Nav titles go through `i18n.t(title)`. | ADR 0005 stands (D89). |
| Core (`@vendure/core` 3.8.1) | `activeChannel` is `@Allow(Authenticated)`. A session's permissions come from `channelPermissions` for the request channel only. | D85. |

**Repo:** `PlatformStaff` does not exist in code yet. `PLATFORM_ONLY_CUSTOM_PERMISSIONS` holds what owners never receive, and an assignable permission missing from it reaches every Owner at the next migrate. `TenantGuard` throws on an archived active channel. ADR 0005's physical-CSS lint rule was never written. No `.tsx` or stylesheet under `plugins/*/dashboard` holds a colour literal or a physical utility today. `@testing-library` and jsdom are not in the repo.

## Review Focus

1. The active store was archived in another tab, or is first in `me.channels`: on the next load the merchant lands on an active store, with no error. Task 5.
2. Selected-store access to the active store was removed mid-session, so the stored token is stale: the shell calls `refreshChannels()` once and recovers without a reload. Task 5.
3. Switching store while on `/stores/<id>/products`: the page follows the new store and does not snap back. Task 5.
4. A member holding no view permission: only Home remains and no empty group shows. Task 4.
5. An Arabic store name of 60 characters with an LTR subdomain at 390 px: truncated, correctly ordered, no horizontal overflow. Task 5.
