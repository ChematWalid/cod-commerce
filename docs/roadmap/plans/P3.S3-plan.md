# P3.S3 Product page, COD form, cart & checkout — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (run through Workflows, ultracode; P3 child rules "lighter workflows": one Opus implementer (tests first) + one reviewer/verifier per task, max one fix round; full adversarial review, 2–3 lenses on Opus, on tasks marked **RISKY**). Steps use checkbox (`- [ ]`) syntax.

**Goal:** A buyer on any store host picks a variant and quantity, fills the COD form (name, phone, wilaya → commune, home/desk with live prices, address/note per settings), sees a live server-priced summary (lines, offers, nudge, discount code, delivery, total), keeps a persistent cart, and submits to the P3.S4 contract (mocked until P3.S4 lands), ending on `/success`.

**Architecture:** Two new signed public endpoints in `plugins/storefront-api` — `POST /store/shipping-quote` over P3.S1's `ShippingQuoteService` and `POST /store/cart-quote` over P2.S4's `PricingService.quoteForScope` (HMAC `quoteToken`), answered through a public projection that hides buyer- and staff-specific reasons — reached by the browser only as same-origin `POST /api/store/*` route handlers that inject the host-resolved store (ADR 0006/0017). The storefront adds client islands under `apps/storefront/src/checkout/**` and `src/cart/**` that hold no business rule: every price, fee, discount, nudge and availability comes from a quote; wilayas/communes come from P3.S1's signed `/store/provinces*` through the same relay, cached per store. Submission goes through an `OrderSubmitPort`; until P3.S4 the `/api/store/orders` handler is a local-only mock.

**Tech Stack:** Next 16.4.5 (cacheComponents, route handlers), React 19.3 client islands, Vendure 3.8.1 plugins (NestJS), zod, vitest 5 (node environment; no DOM library), playwright-core (browser tests via vitest).

## Review Focus

1. **Client-controlled pricing:** a body `channel: 'dashboard'`, `addons`, `waive`, `storeId`, `businessId`, `productId` in cart-quote lines, or a price field → stripped/forced; waive never read (Tasks 4, 5).
2. **Buyer and staff data through the public quote:** a phone probe revealing order history (`audience`, `per_buyer_limit` reasons), staff-only offer ids (`channel` skips) → removed or generalised by the public projection (Task 5).
3. **Cross-store quoting:** store B's ids on host A → B's prices never appear; an A token fails `verifyQuoteForScope` for B (Tasks 5, 11).
4. **Relay abuse:** foreign `Origin`, a streamed body past the cap, non-JSON, a query on POST, a client `storeId` → refused before any upstream call; upstream errors relayed as `{ code }` only (orders 409 adds the validated fresh quote); provinces flood served from the per-store cache (Task 6).
5. **Token/cart drift at submit:** any field the token covers (lines, destination, codes, phone) changed since the last answer, a near-expiry token on a skewed device clock, a server 409 → silent re-quote and, when the total changed, the new summary shown instead of submitting (Tasks 8, 10).
