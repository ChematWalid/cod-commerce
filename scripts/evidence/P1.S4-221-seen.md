  then six plain and two CPU-throttled (×4) loops of the 390 px RTL test and `account-menu-close`.
- **`before.md`, 16 / 0.** The old helper (`closeMenus`, the four #221 files swapped back to `8fa54c1`) also passed the same

- **Why the fix stands anyway.** It removes a wait that can never resolve, by reading the code rather than by a run: the old
  helper took `before` from `getByRole('menu').count()`, which skips ARIA-hidden nodes, and then waited for
  `querySelectorAll('[role="menu"]').length < before`, which counts every node. A closing popup keeps `role=menu` until
  its exit animation ends, so any hidden menu node at count time leaves the predicate false after a correct close. The new
  helper waits on the trigger's own open state (`aria-expanded`, `data-popup-open`), which both counts agree on, and
  reports a stuck menu with a state dump instead of a bare timeout. No timeout was raised.
- **What to watch.** If #221 reappears in CI after this merge, the `MenuCloseError` dump names the menu that stayed open.
